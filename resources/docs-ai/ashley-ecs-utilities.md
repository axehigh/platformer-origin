# Non-ECS helpers & shared state (Ashley-ECS companion)

Part of the ashley-ecs documentation set — index: `ashley-ecs.md`

### `RoomState` (`com.axehigh.platformer.map.RoomState`, not an ECS `Component`)
A plain shared-state holder (same sharing pattern as the shared `collisionRects` array, not a `Component`/`System`) built from a map's **"Rooms" object layer**: `Array<Room> rooms` (every room rectangle from that layer, parsed by `MapLoader.getRooms()`) and `int activeRoomIndex = -1` (index into `rooms` of whichever one currently contains the player). Exposes `findRoomIndexContaining(float x, float y)`, a linear scan returning the first room rectangle containing that point, or `-1`. A single instance is created once in `GameScreen.show()`, passed to `CameraSystem` (see `ashley-ecs-systems.md`), `EnemySystem`, `EnemyShootSystem`, `EnemyAttackSystem`, `MovingPlatformSystem`, `DebugRenderSystem`, `EntityFactory.spawnObjects(...)`, and `LevelManager`; `LevelManager.loadLevel(...)` clears+refills `rooms` in place on every level swap, so every holder sees the new level's rooms immediately, no re-wiring needed â€” identical in spirit to how `collisionRects` is shared.

### `Room` (`com.axehigh.platformer.map.Room`, not an ECS `Component`)
A plain `Rectangle` subclass carrying one extra field â€” the camera-mode override. `Array<Room>` is what `RoomState.rooms` actually holds, so any consumer reading a room as a plain `Rectangle` (e.g. `DebugRenderSystem`, `CameraSystem`; see `ashley-ecs-systems.md`) keeps working unchanged. Field: `Mode mode` (`AUTO`, `FLIP`, or `SCROLL`), parsed by `MapLoader.getRooms()` from the room's optional `camera` Tiled custom property (`"flip"`/`"scroll"`; anything else = `AUTO`). `CameraSystem` resolves the effective mode **per axis**: `AUTO` infers from size (room bigger than the viewport on an axis â†’ scroll, otherwise â†’ static center), `FLIP` forces static room-centered framing, `SCROLL` forces dead-zone scrolling (still falling back to centering when the room is smaller than the viewport, since there is nothing to scroll).

### `SecretRoom` (`com.axehigh.platformer.map.SecretRoom`, not an ECS `Component`)
Plain data holder for one **hidden** secret room (see `map-design-for-tiled.md` Â§3.6), grouped by `MapLoader.getSecretRooms()` from three map artifacts linked by a shared room name: `String name` (matched against the `Rooms` rect's object name, the secret wall tile's `secretRoom` property, and the deferred markers' `secretRoom` object property), `Room room` (the matching `Rooms` rect, `null` if absent), `Array<Rectangle> walls` (the `secret=true` + `secretRoom` collision-layer wall rects protecting this room), `Array<Rectangle> veilCells` (the `secret_hide`-layer cells (as world-space rects) blanked on reveal), `MapObjects deferredObjects` (the loot/enemy markers partitioned OUT of the normal `objects`/`enemies` spawn layers), and `boolean revealed` (idempotency gate so breaking two walls of the same room reveals + spawns exactly once).

### `SecretRoomRevealer` (`com.axehigh.platformer.map.SecretRoomRevealer`, not an ECS `Component`/`System`)
Engine-side service that makes a hidden secret room appear. Constructed once in `GameScreen.show()` with the `PooledEngine`, `EntityFactory`, and shared `RoomState`; `LevelManager.loadLevel(...)` re-seeds it on every level swap via `setRooms(Array<SecretRoom>)` + `setHideLayer(TiledMapTileLayer)` (null-safe â€” plain maps without hidden rooms keep it a no-op). `reveal(String roomName)` (idempotent, gated by `SecretRoom.revealed`) blanks every veil cell in the `secret_hide` layer (`cell.setTile(null)` â€” purely visual; collision stays solely in the `collision` layer), spawns the room's deferred markers via `EntityFactory.spawnObjects(engine, room.deferredObjects, roomState)` exactly once, and spawns a `ParticleHelper.spawnSmallSmoke` puff at each veil-cell center. Called by `MeleeAttackSystem.breakSecretWall(...)` (see `ashley-ecs-systems.md`) when the struck wall's tile carries a `secretRoom` property; `isRevealed(String)` exposes the per-room gate.

### `CrumblingTile` (`com.axehigh.platformer.map.CrumblingTile`, not an ECS `Component`)
A plain shared-state holder (same pattern as the shared `collisionRects` array / `RoomState`, not a `Component`) for one crumbling-platform tile, parsed by `MapLoader` from a collision-layer tile flagged `crumble=true` (see `map-design-for-tiled.md` §3.4). Fields: `TiledMapTileLayer layer` (the collision layer the tile lives on; its cell is blanked on collapse and restored on respawn), `int cellX`/`cellY` (grid coordinates on `layer`), `TiledMapTileLayer.Cell originalCell` (captured at map build time, restored on respawn), `Rectangle rect` (world-space full-tile rect — **the same instance** also present in the shared `oneWayRects` array, so identity add/remove keeps them in sync), `State state` (enum: `INTACT` / `SHAKING` / `COLLAPSED` — the shake → collapse → respawn cycle), the four `Timer` fields `shakeTimer` (visible shake before collapse), `respawnTimer` (delay before respawning), `contactTimer` (arming grace / graze guard — reset whenever contact breaks), `settleTimer` (post-respawn grace blocking instant re-arm), and `boolean wasOverlapped` (last frame's overlap — makes arming edge-triggered, so a fresh contact entry is required). The state machine lives in `CrumblingTileSystem` (see `ashley-ecs-systems.md`); `LevelManager.loadLevel(...)` refills the shared tile array in place with fresh `INTACT` instances.

### `Timer` (`com.axehigh.platformer.util.Timer`)
A plain (non-`Component`, non-`Poolable`) helper class embedded as a field inside components that need a countdown â€” not an Ashley concept, just a reusable value holder. API: `start(float duration)`, `update(float deltaTime)` (clamped at 0, no-op once done), `isActive()`, `isDone()`, `getRemaining()`, `reset()`. Used by `PlayerComponent` (`shootCooldown`, `meleeCooldown`, `meleeAttack`, `hitInvulnerability`, `hurtTimer`, `dropWindow`, `idleHold`, `potionCooldown`), `BuffComponent` (`strength`, `speed`, `invulnerability`), `ChestComponent` (`disappearTimer`), `EnemyComponent` (`hitStun`), `EnemyShooterComponent` (`shootCooldown`, `windUp`, `turnIdle`), and `EnemyAttackComponent` (`attackCooldown`, `windUp`, `strike`); **any new cooldown/countdown/grace-period field should use `Timer` instead of a raw `float`.**

### `FeatureFlags` (`com.axehigh.platformer.util.FeatureFlags`, not an ECS `Component`)
A session-wide static holder for developer feature flags (same spirit as `RoomState`/`collisionRects` â€” shared runtime state, not an Ashley concept), mirroring the static-toggle pattern of `DebugRenderSystem.debugEnabled` (see `ashley-ecs-systems.md`) but persistence-backed. Statics are seeded once from `GamePreferences` on first read and survive level reloads within a session; setters also persist them across app restarts. All access is safe without a running `Gdx` application (headless tests): reads fall back to the documented default, writes update the static without persisting. Current flags: `wallClimbingEnabled` (default `true`) â€” gating the wall-climb mechanic in `MovementSystem` (wall-slide gravity + the `jumpCount = 1` wall-jump latch; when OFF the player never latches and falls at full gravity), toggled live from the pause dialog's "Wall Climb" button and the Settings screen's Gameplay tab. This is the first step towards replacing wall-climb with ladder/vine traversal. `squashEnabled` (default `false`) â€” gating the player landing squash pulse. `selectLevelEnabled` (default `true`) â€” gating whether the main menu shows its Select Level entry (checked when `MainMenuScreen.show()` builds its UI). `softStopEnabled` (default `true`, persisted key `softStopEnabled`) â€” gating the player's soft ramp-down into idle: the ground-friction deceleration in `PlayerInputSystem` (the no-direction branch, which otherwise hard-zeroes `velocity.x` the frame direction is released) plus the `PLAYER_IDLE_DELAY` pose hold in `AnimationSystem` (the idle-entry arming/hold-return, skipped entirely when OFF so the player snaps straight to `IDLE` the same frame); toggled live from the pause dialog's "Soft Stop" button and the Settings screen's Gameplay tab. `vignetteEnabled` (default `true`, persisted key `vignetteEnabled`) â€” gating the screen-framed room/map-edge vignette (`VignetteRenderSystem`, a pure visual, no gameplay effect); toggled live from the pause dialog's Debug tab and the Settings screen's Debug tab. `slashArcEnabled` (default `true`, persisted key `slashArcEnabled`) â€” the project's **combat-effects** toggle: gates **both** the melee slash-arc VFX (the seeded arc on each swing, see the `SlashArcSystem` row in `ashley-ecs-systems.md`) **and** the white hit-flash tint on damage (`HitFlashSystem`, see its row in `ashley-ecs-systems.md`), so flipping it OFF disables both cosmetic combat effects; toggled live from the pause dialog's Debug tab ("Combat FX" box) and the Settings screen's Debug tab ("Combat Effects" box).

### `EnemyDamageResolver` (`com.axehigh.platformer.ecs.systems.EnemyDamageResolver`)
A package-private static helper (not a `Component`/`System`) shared by `PlayerBulletSystem` (bullet hits) and `MeleeAttackSystem` (melee hits; both in `ashley-ecs-systems.md`) so both damage sources apply enemy hit-reaction identically. `canBeHit(EnemyComponent enemy)` — the single source of truth for "this enemy can currently take a hit": `!enemy.isDead && !enemy.hitStun.isActive()` (the post-hit recovery idle is NOT immune — a valid re-hit/combo window); `applyHit` uses it for its immunity guard and `MeleeAttackSystem` uses it for the hit-commitment dampen, so the hittability rule lives in one place. `applyHit(Entity enemyEntity, EnemyComponent enemy, MovementComponent movement, float damage, int knockbackDirection, boolean isFlying, float unitScale, PooledEngine engine)`: if `!canBeHit(enemy)` the hit is fully ignored (returns `false`). Otherwise subtracts `damage` from `enemy.health`. If health reaches 0, sets `enemy.isDead = true`, zeroes `movement.velocity`, starts `enemy.deathTimer` based on the `DEATH` animation duration **plus** the package-visible `DEATH_FLASH_DURATION` (`0.8s` â€” the corpse's post-animation blink window, driven by `AnimationSystem`), and returns `true`; on that kill frame it also spawns a one-shot **death-burst VFX** at the enemy's collision center when an engine is supplied (`spawnDeathBurst` → `ParticleHelper.spawnDeathBurst(engine, centerX, centerY, color)`: a smoke poof plus a recolored `SPARKS` clone tinted spectral blue for `FlyingEnemyComponent` enemies / dark red otherwise via the `GameConstants.DEATH_BURST_COLOR_*` palette), gated on `FeatureFlags.isSlashArcEnabled()` — the same combat-effects flag as the hit-flash/slash-arc, so flag OFF leaves the death flow exactly as before. Otherwise, sets `movement.velocity.x` to a knockback pop (`130` u/s horizontal away from the attacker) and, unless `isFlying`, a `140` u/s vertical hop, starts `enemy.hitStun` for a duration matching the `HURT` animation (min `0.3s`), spawns a one-shot spark burst at the enemy's center when an engine is supplied (`GlobalParticles.SPARKS`, scale `1.2`, hard `maxLifetime` `1.0s` â€” `HIT_SPARK_SCALE`/`HIT_SPARK_MAX_LIFETIME`, package-visible and reused by `MeleeAttackSystem`'s wall clank), and returns `false`.

### `PlayerDamageResolver` (`com.axehigh.platformer.ecs.systems.PlayerDamageResolver`)
The player-side counterpart of `EnemyDamageResolver`: a package-private static helper shared by `EnemyContactSystem` (touch), `EnemyBulletCollisionSystem` (enemy bullet), `HazardSystem` (hazard tiles), and `EnemyAttackSystem` (melee attack; all in `ashley-ecs-systems.md`) so all player damage sources apply the same hit-reaction. `applyHit(Entity playerEntity, PlayerComponent player, MovementComponent movement, int knockbackDirection, float unitScale)`: if `player.isDead` or `player.hitInvulnerability.isActive()` â€” or the player's Invulnerability potion buff is active (`BuffComponent.invulnerability`, looked up defensively via the `BUFF` mapper) â€” the hit is fully ignored (returns `false`); otherwise decrements `player.health` (clamped at 0), sets `movement.velocity.x` to a small knockback push (`60` u/s horizontal, direction given by `knockbackDirection` â€” no vertical pop), starts `player.hurtTimer` for a duration matching the `HURT` animation (min `0.3s`, so the clip visibly plays once), and starts `player.hitInvulnerability` for `2.0s`. Returns `true` if the hit applied. `applyHitWithoutKnockback(Entity playerEntity, PlayerComponent player)`: the **no-knockback** variant used by `HazardSystem` â€” same guard (including the buff check), health decrement, `hurtTimer`, and `hitInvulnerability` bookkeeping, but the player's `MovementComponent.velocity` is left completely untouched, so a hazard touch damages without shoving the player (appropriate for static hazard tiles where there's no meaningful "attacker direction"). Both funnel through a private `applyStunAndGrace(...)` for the shared stun/grace bookkeeping, and both fire the **damage vignette pulse** right after the health decrement: `VignetteRenderSystem.triggerPulse()` (same package, no import needed) arms the static red vignette flash on the renderer side, so every form of player damage â€” touch, bullet, melee, hazard â€” flashes the screen edges identically. Both variants also fire the player-damage SFX at the same choke point: `applyHit(...)` plays the placeholder `SFX_PLAYER_HURT` (knockback damage — enemy contact, enemy melee, enemy bullets) and `applyHitWithoutKnockback(...)` the placeholder `SFX_PLAYER_HAZARD` (hazards/traps), both `sfx/PowerUp11.mp3`, routed through the `SfxSystem` installed via the static `setSfxSystem(SfxSystem)` seam (null-safe — unit tests leave it unset and never crash). Because the sound fires only after the pre-damage guards (dead / invulnerability / buff) pass, at most one fire occurs per landed hit. `HIT_INVULNERABILITY_DURATION = 2.0f` is the single source of truth for the grace period all callers share.

### `LevelManager` (`com.axehigh.platformer.map.LevelManager`, not an ECS `Component`/`System`)
Owns in-place level transitions on behalf of `LevelExitSystem` (see `ashley-ecs-systems.md`): `loadLevel(String tmxPath, Entity player)` loads a new `MapLoader`, calls `TiledMapRenderSystem.setMap(...)`, clears+refills the shared `collisionRects`, `oneWayRects`, `crumblingTiles` (an injected constructor parameter — `Array<CrumblingTile>` — handled exactly like the other shared sets), `hazardRects`, and `secretRects` arrays **and** the shared `RoomState.rooms` array in place (so `MovementSystem`/`EnemySystem`/`PlayerBulletSystem`/`EnemyBulletCollisionSystem`/`HazardSystem`/`MeleeAttackSystem`/`DebugRenderSystem`/`CameraSystem`/`CrumblingTileSystem` all see the new level's walls/one-way platforms/crumbling tiles/hazards/secret walls/rooms immediately, no re-wiring; the freshly pushed `CrumblingTile` instances are all `INTACT` with zeroed timers, so a mid-crumble tile resets for free), pushes the new map's collision tile layer into `MeleeAttackSystem.setCollisionLayer(...)` so secret-wall cells are blanked correctly, re-seeds the injected `SecretRoomRevealer` with `setRooms(mapLoader.getSecretRooms())` + `setHideLayer(mapLoader.getSecretHideLayer())` so the new level's hidden rooms re-arm, removes every engine entity except the given player, disposes the old `MapLoader`, respawns the new level's objects via `EntityFactory.spawnObjects(...)` (which assigns each spawned enemy's and moving platform's `roomIndex` from the new `RoomState`), repositions the player's `TransformComponent` to the new map's `playerStart`, resets its transient `MovementComponent` (`velocity`, `grounded`) and `PlayerComponent` flags (`jumpCount`, `isWallClimbing`, `interactPressed`, `nearExit`, `dropRequested`, `onDropTile`, `dropWindow`, `idleHold`, `idleHoldArmed`, plus the airborne/squash transients `inAir`, `maxAirHeight`, `squashActive`, `squashAmount`) while leaving all stat fields (`health`, `coins`, `ammo`, ...) untouched, pushes the new map's `unitScale` into every scale-dependent system including `MovingPlatformSystem.setUnitScale(newScale)` (so the landing-dust 1-tile height gate matches the new map), and calls `CameraSystem.snapToRoom(..., bandZoom)` to place the camera in the new starting room (the `bandZoom` flag is forwarded from `GameScreen.applyLayoutMode()` via `setBandZoom(boolean)`). `dispose()` disposes whichever `MapLoader` is currently active. Constructed once in `GameScreen.show()` (constructor takes the shared `RoomState`, `collisionRects`, `oneWayRects`, `hazardRects`, `secretRects`, `EntityFactory`, `TiledMapRenderSystem`, `MeleeAttackSystem`, `MovingPlatformSystem`, `CameraSystem`, and the `SecretRoomRevealer`) and never rebuilt; the player `Entity`/`PooledEngine` are never destroyed across a level swap, which is why every persistent `PlayerComponent` field survives for free.
