# Ashley ECS Reference

This document is the **single source of truth for the ECS layer** (`com.axehigh.platformer.ecs`): every `Component` and every `System` currently implemented, what data/behavior it owns, and how systems are wired together at runtime. It is written to be consumed by an AI agent before making any ECS change, so keep it terse, structured, and exhaustive rather than narrative.

> **Maintenance rule:** Any time a `Component` or `System` is added, removed, renamed, or has its fields/behavior/family/priority changed, this file MUST be updated in the same change. This is the ECS counterpart to the `gameplay.md` sync rule in `AGENTS.md`.

## 1. Components (`com.axehigh.platformer.ecs.components`)

| Component | Poolable | Fields | Purpose |
|---|---|---|---|
| `TransformComponent` | Yes | `Vector2 position`, `Vector2 scale = (1,1)`, `float rotation`, `float z` | World position, scale (also used to flip sprites via negative `scale.x`), rotation, and z-layer draw order. |
| `TextureComponent` | Yes | `TextureRegion region` | The currently visible texture region for an entity; `null` region is skipped by `RenderSystem`. |
| `AnimationComponent` | No | `ObjectMap<State, Animation<TextureRegion>> animations`, `State currentState/previousState = IDLE`, `float stateTime` | Per-state animation clips and playback timer. `State` enum: `IDLE, RUNNING, JUMPING, DOUBLE_JUMPING, WALL_CLIMBING, ATTACKING`. |
| `MovementComponent` | Yes | `Vector2 velocity`, `Vector2 acceleration`, `float maxSpeedX = 100`, `float maxSpeedY = 400`, `boolean grounded` | Velocity/acceleration and speed clamps consumed by `MovementSystem` (or `CollisionSystem` for bullets). |
| `CollisionComponent` | Yes | `Rectangle bounds` | AABB bounding box, relative-sized (positioned each frame from `TransformComponent.position`). |
| `PlayerComponent` | No | `int health/maxHealth = 3`, `int coins = 0`, `int items/maxItems = 0/30`, `int facingDirection = 1` (-1 left, 1 right), `int jumpCount`, `int maxJumps = 2`, `boolean isWallClimbing`, `Timer shootCooldown`, `Timer meleeCooldown`, `Timer meleeAttack`, `boolean meleeHasHit`, `Timer hitInvulnerability`, `boolean interactPressed`, `boolean nearExit` | Flag + state component for the single player entity: health, currency, ammo, traversal (double jump, wall climb), combat (melee/ranged) state, the post-hit invulnerability grace period, and the exit-gate interact flow (`interactPressed` is a one-shot per-frame flag set by `PlayerInputSystem`, `nearExit` drives the touch UI prompt and is set by `LevelExitSystem`). All of these survive a `LevelManager.loadLevel(...)` swap untouched except `interactPressed`/`nearExit`, which are explicitly reset (along with transient movement state) since it's literally the same component instance kept alive across levels. |
| `BulletComponent` | Yes | `float damage`, `float lifetime` | Marks a spawned projectile entity; despawns once `lifetime` elapses without a hit. `damage` is `0` for enemy-fired bullets (see `EnemyBulletComponent`), since those damage the player via the flat contact-damage rule, not HP damage. |
| `EnemyComponent` | No | `float health = 10`, `float speed = 20`, `int direction = 1` (1=right, -1=left), `float patrolRange = 32`, `float originX`, `Timer hitStun`, `int roomIndex = -1` | Damageable enemy with simple back-and-forth patrol movement resolved by `EnemySystem` (direction/velocity are stored here so the system stays stateless between entities); damage is applied externally by `CollisionSystem`/`MeleeAttackSystem`, which also start `hitStun` (a post-hit grace period during which patrol AI pauses and further hits are ignored). `roomIndex` is the index into `RoomState.rooms` of the Room rectangle this enemy was spawned inside of (set by `EntityFactory` from the spawn point's containment), or `-1` if it wasn't inside any known room (always active); `EnemySystem`/`EnemyShootSystem` freeze this enemy's patrol/firing while `roomIndex` doesn't match `RoomState.activeRoomIndex`. |
| `FlyingEnemyComponent` | No | `float bobAmplitude = 8`, `float bobFrequency = π` (rad/s), `float bobTime` | Layered on top of `EnemyComponent` to tag an enemy as immune to gravity; checked by `MovementSystem`, which skips the gravity/wall-slide velocity-Y update entirely when present, so the entity hovers at whatever height it's at (no bobbing without a horizontal velocity source, since gravity never pulls it back). `EnemySystem` also drives a time-based vertical bob wave into `movement.velocity.y` from `bobAmplitude`/`bobFrequency`/`bobTime` every non-stunned frame, so the flyer flaps up/down around its spawn height while patrolling; `bobTime` freezes whenever patrol AI is paused (hit-stun). Horizontal patrol logic needs no changes: a flying enemy is never `grounded`, so it turns around purely via `patrolRange`/`originX`. |
| `EnemyShooterComponent` | No | `Timer shootCooldown`, `float shootInterval = 5` | Layered on top of `EnemyComponent` to tag an enemy as able to fire a bullet periodically; resolved by `EnemyShootSystem`, which additionally only lets a ready shooter actually fire while its `EnemyComponent.roomIndex` is the currently active Room (see `EnemyShootSystem` row below). The enemy still patrols normally (driven by `EnemySystem`, which already matches its family). |
| `EnemyBulletComponent` | Yes | *(none — empty marker)* | Tags a bullet entity as enemy-fired (as opposed to the player's own bullets), attached alongside `BulletComponent` by `EnemyShootSystem`. `CollisionSystem` excludes it; `EnemyBulletCollisionSystem` processes it instead. |
| `CoinPickupComponent` | No | `int amount = 1` | Marker for a coin pickup; grants `amount` to `PlayerComponent.coins` (uncapped) on pickup. |
| `DaggerPickupComponent` | No | `int amount = 5` | Marker for a dagger pickup; grants `amount` to `PlayerComponent.items`, capped at `maxItems`. |
| `ChestComponent` | No | `boolean opened = false`, `Timer disappearTimer` | Tracks a chest's open/disappear state after being melee-struck; drops coins on disappear. |
| `PoppedItemComponent` | No | *(none — empty marker)* | Tags a pickup entity (currently only chest-dropped coins) that was launched with an initial `MovementComponent.velocity`; checked by `MovementSystem`, which zeroes `velocity.x` the moment `grounded` first becomes true so it comes to a dead stop on landing instead of sliding (there's no ground friction elsewhere). |
| `LevelExitComponent` | No | `String nextLevelPath = ""` | Marks an exit-gate entity as an actual level-transition trigger (as opposed to a purely decorative gate); added by `EntityFactory.createExitGate(...)` only when the gate's Tiled object has a `nextLevel` custom property. Read by `LevelExitSystem`, which hands `nextLevelPath` to `LevelManager.loadLevel(...)`. |

### `Mappers` (`com.axehigh.platformer.ecs.components.Mappers`)
Central holder of shared `ComponentMapper<T>` instances (one static field per component above: `TRANSFORM`, `TEXTURE`, `ANIMATION`, `MOVEMENT`, `COLLISION`, `PLAYER`, `BULLET`, `ENEMY_BULLET`, `ENEMY`, `FLYING`, `ENEMY_SHOOTER`, `DAGGER_PICKUP`, `COIN_PICKUP`, `CHEST`, `POPPED_ITEM`, `LEVEL_EXIT`). **Every system must read/write components through these mappers** instead of creating new `ComponentMapper.getFor(...)` calls. Adding a new component requires adding its mapper here.

### `RoomState` (`com.axehigh.platformer.map.RoomState`, not an ECS `Component`)
A plain shared-state holder (same sharing pattern as the shared `collisionRects` array, not a `Component`/`System`) built from a map's **"Rooms" object layer**: `Array<Rectangle> rooms` (every rectangle from that layer, parsed by `MapLoader.getRooms()`) and `int activeRoomIndex = -1` (index into `rooms` of whichever one currently contains the player). Exposes `findRoomIndexContaining(float x, float y)`, a linear scan returning the first room rectangle containing that point, or `-1`. A single instance is created once in `GameScreen.show()`, passed to `CameraSystem`, `EnemySystem`, `EnemyShootSystem`, `DebugRenderSystem`, `EntityFactory.spawnObjects(...)`, and `LevelManager`; `LevelManager.loadLevel(...)` clears+refills `rooms` in place on every level swap, so every holder sees the new level's rooms immediately, no re-wiring needed — identical in spirit to how `collisionRects` is shared.

### `Timer` (`com.axehigh.platformer.util.Timer`)
A plain (non-`Component`, non-`Poolable`) helper class embedded as a field inside components that need a countdown — not an Ashley concept, just a reusable value holder. API: `start(float duration)`, `update(float deltaTime)` (clamped at 0, no-op once done), `isActive()`, `isDone()`, `getRemaining()`, `reset()`. Used by `PlayerComponent` (`shootCooldown`, `meleeCooldown`, `meleeAttack`, `hitInvulnerability`), `ChestComponent` (`disappearTimer`), `EnemyComponent` (`hitStun`), and `EnemyShooterComponent` (`shootCooldown`); **any new cooldown/countdown/grace-period field should use `Timer` instead of a raw `float`.**

### `EnemyDamageResolver` (`com.axehigh.platformer.ecs.systems.EnemyDamageResolver`)
A package-private static helper (not a `Component`/`System`) shared by `CollisionSystem` (bullet hits) and `MeleeAttackSystem` (melee hits) so both damage sources apply enemy hit-reaction identically. `applyHit(EnemyComponent enemy, MovementComponent movement, float damage, int knockbackDirection, boolean isFlying)`: if `enemy.hitStun.isActive()`, the hit is fully ignored (returns `false`, no damage/knockback); otherwise subtracts `damage` from `enemy.health` and, if the enemy survives, sets `movement.velocity.x` to a knockback pop (`90` u/s horizontal away from the attacker per `knockbackDirection`) and, unless `isFlying` is `true`, also sets `movement.velocity.y` to a `140` u/s vertical hop (skipped for flyers, which have no gravity to pull them back down), then starts `enemy.hitStun` for `0.3s`; returns `true` if the enemy's health reached 0 (caller removes the entity).

## 2. Systems (`com.axehigh.platformer.ecs.systems`)

Each row lists the Ashley base class, the entity `Family` it processes (as configured in its constructor), and its responsibility. "Priority" refers to the value passed in by `GameScreen` (lower runs first); systems are also usable with priority `0` via their no-arg/short constructors for tests or other screens.

| System | Base class | Family | Responsibility |
|---|---|---|---|
| `PlayerInputSystem` | `IteratingSystem` | all: `PlayerComponent`, `MovementComponent`, `TransformComponent`, `CollisionComponent` | Reads keyboard **and** touch-UI input (state pushed in via `setTouchLeft/Right`, `requestTouchJump/Melee/Shoot`) and converts it into: horizontal velocity + `facingDirection`; jump velocity (gated by `jumpCount < maxJumps`); melee trigger (gated by `meleeCooldown.isDone()`, starts `meleeAttack`); ranged shot (gated by `shootCooldown.isDone()` and `items > 0`, spawns a bullet entity via `PooledEngine` with `BULLET_DAMAGE = 10`). Touch-request flags are reset every `update()` after processing. |
| `EnemySystem` | `IteratingSystem` | all: `EnemyComponent`, `MovementComponent`, `TransformComponent`, `CollisionComponent` | Simple back-and-forth patrol AI, plus platform-edge awareness, hit-stun pausing, and Room-based activation. Each frame ticks `enemy.hitStun`. First checks whether `enemy.roomIndex` (see `EnemyComponent`) is either `-1` or equal to `RoomState.activeRoomIndex`; if not, the enemy is frozen entirely — `movement.velocity.x` (and `velocity.y` for a `FlyingEnemyComponent`) is zeroed and patrol/bob logic is skipped for the frame. Otherwise, while `hitStun` is active, patrol AI is skipped (lets a knockback pop play out via `MovementSystem` uninterrupted); otherwise sets `movement.velocity.x = enemy.speed * enemy.direction`, flipping `direction` when: strayed `patrolRange` past `originX` in either direction; blocked by a wall (`grounded && velocity.x == 0`, i.e. `MovementSystem` zeroed it after a wall hit last frame); or about to walk off a ledge (a small ground-sensor probe rectangle just past the leading foot and below it, checked against the same static `collisionRects` `MovementSystem` uses — no ground there means turn around). A `FlyingEnemyComponent` enemy is never `grounded`, so its wall-block/ledge checks never fire and it turns purely on `patrolRange`; it also gets a time-based vertical bob wave written into `movement.velocity.y`. Runs **before** `MovementSystem` so the velocity it sets is integrated the same frame; gravity/wall collision for enemies come for free from `MovementSystem` since Transform+Movement+Collision (non-bullet) entities already match its family. Holds a `RoomState` reference passed in via its constructor. |
| `EnemyShootSystem` | `IteratingSystem` | all: `EnemyComponent`, `EnemyShooterComponent`, `TransformComponent`, `CollisionComponent` | Drives shooter-enemy firing: caches a `PooledEngine` in `addedToEngine`; each frame ticks `shooter.shootCooldown`, skips firing entirely while `enemy.hitStun.isActive()` (mirrors `EnemySystem`'s own stun-pause), and once `isDone()` **and** `enemy.roomIndex` is either `-1` or equal to `RoomState.activeRoomIndex`, spawns a bullet (reusing `gfx/bullet.png`, tagged with both `BulletComponent`, `damage = 0`, and `EnemyBulletComponent`) at the enemy's edge, traveling horizontally in `enemy.direction` — no player-aiming/aggro — then restarts the cooldown via `shootInterval`. While the shooter's room isn't the active one, `shootCooldown` simply idles at done (never restarted), so the shooter fires immediately once its room becomes active again; no bullet ever crosses a room boundary since firing itself is gated, not just despawned after the fact. Holds a `RoomState` reference passed in via its constructor. |
| `MovementSystem` | `IteratingSystem` | all: `TransformComponent`, `MovementComponent`, `CollisionComponent`; **excludes** `BulletComponent` | Applies gravity (or reduced wall-slide gravity while `isWallClimbing`), unless the entity has a `FlyingEnemyComponent` (gravity/wall-slide velocity-Y update is skipped entirely, so it holds its spawn height). Clamps velocity to `maxSpeedX/Y`, integrates position on X then Y separately with AABB resolution against the static `collisionRects` set (from `MapLoader`). If the entity has a `PoppedItemComponent` and just became `grounded`, also zeroes `velocity.x` so it stops dead on landing instead of sliding. Drives player-only side effects: resets `jumpCount` when grounded, sets `isWallClimbing`/`jumpCount = 1` on a horizontal wall hit while airborne, and clears `isWallClimbing` on release. |
| `CollisionSystem` | `IteratingSystem` | all: `BulletComponent`, `TransformComponent`, `MovementComponent`, `CollisionComponent`; **excludes** `EnemyBulletComponent` | Owns **player-bullet-only** movement integration (bullets are excluded from `MovementSystem`) and resolution: counts down `lifetime` (removes on expiry), moves the bullet, removes it on wall overlap (`collisionRects`), and on enemy overlap resolves the hit via `EnemyDamageResolver.applyHit(...)` (knockback direction = the bullet's own travel direction, `isFlying` = whether the hit enemy has `FlyingEnemyComponent`), removing the enemy if it died, and always removes the bullet. Looks up the enemy family once in `addedToEngine`. Excludes `EnemyBulletComponent` so it never double-processes an enemy-fired bullet (handled instead by `EnemyBulletCollisionSystem`). |
| `EnemyBulletCollisionSystem` | `IteratingSystem` | all: `BulletComponent`, `EnemyBulletComponent`, `TransformComponent`, `MovementComponent`, `CollisionComponent` | Mirrors `CollisionSystem`'s structure for **enemy-fired** bullets only, but resolves the hit case against the player instead of an enemy: caches the single player entity once in `addedToEngine` (mirrors `PickupSystem`); counts down `lifetime` (removes on expiry), moves the bullet, removes it on wall overlap, and on player overlap always removes the bullet, additionally — only if `player.hitInvulnerability.isDone()` — decrementing `player.health` by `1` (clamped at `0`) and restarting `player.hitInvulnerability` for `1.0s` (the same shared timer `EnemyContactSystem` uses, so a shot and a touch share one grace period). |
| `MeleeAttackSystem` | `IteratingSystem` | all: `PlayerComponent`, `TransformComponent`, `CollisionComponent` | While `meleeAttack.isActive()` and `!meleeHasHit`, builds a short strike `Rectangle` offset from the player's bounds in `facingDirection` (width `STRIKE_WIDTH = 10`) and checks it against the enemy family first, then the chest family (looked up once in `addedToEngine`). Resolves an enemy hit via `EnemyDamageResolver.applyHit(...)` (`MELEE_DAMAGE = 5`, knockback direction = `facingDirection`, `isFlying` = whether the hit enemy has `FlyingEnemyComponent`), removing the enemy if it died, **or** opens an unopened chest (swaps texture to `gfx/chest_open.png`, starts `disappearTimer`); either way sets `meleeHasHit = true` so one swing hits at most once. Ticks `meleeAttack` down every frame it runs. |
| `PickupSystem` | `IteratingSystem` | one of: `DaggerPickupComponent`, `CoinPickupComponent` | Resolves the single player entity once in `addedToEngine`, then per pickup entity checks AABB overlap against the player. On overlap: dagger pickups increment `player.items` (capped at `maxItems`), coin pickups increment `player.coins` (uncapped); either way removes the pickup entity. |
| `ChestSystem` | `IteratingSystem` | all: `ChestComponent`, `TransformComponent` | Owns the opened-chest lifecycle: for chests with `opened == true`, ticks `disappearTimer` down; once `isDone()`, removes the chest and spawns a random number (`MathUtils.random(2, 6)`) of coin pickups (via `EntityFactory.createPoppedCoinPickup`) at the chest's last position, each launched with a random upward (`80`-`140` u/s) and horizontal (`±40` u/s) velocity so it pops up and out before `MovementSystem`'s gravity/collision settles it on the ground. |
| `EnemyContactSystem` | `IteratingSystem` | all: `EnemyComponent`, `TransformComponent`, `CollisionComponent` | Resolves enemy-vs-player contact damage: resolves the single player entity once in `addedToEngine` (mirroring `PickupSystem`); overrides `update(float deltaTime)` to tick `player.hitInvulnerability` exactly **once per frame** (before `super.update()` iterates enemies, avoiding a multi-tick bug with 2+ enemies), then per enemy checks AABB overlap against the player. On overlap while `hitInvulnerability.isDone()`: decrements `player.health` by `1` (clamped at `0` via `Math.max`) and starts a `1.0s` `hitInvulnerability` grace period, so a single frame with multiple overlapping enemies still only costs one life. Note: this is the same timer `EnemyBulletCollisionSystem` reads/restarts, so contact and shot damage share one grace period. |
| `LevelExitSystem` | `IteratingSystem` | all: `LevelExitComponent`, `TransformComponent`, `CollisionComponent` | Drives the exit-gate proximity/interact flow, mirroring `EnemyContactSystem`'s single-player-resolved-once pattern: resolves the single player entity once in `addedToEngine`; each frame first resets `player.nearExit = false`, then per gate builds a sensor `Rectangle` (the gate's own `CollisionComponent.bounds` inflated by `SENSOR_PADDING = 6` units on every side) and checks it against the player's AABB. On overlap sets `player.nearExit = true` (drives the touch UI prompt); if `player.interactPressed` is also `true` that same frame, consumes the flag (`= false`), builds/persists a `SaveData` snapshot (level path, core stats, merged `completedLevelIds`) via `SaveManager.save(...)`, and calls `LevelManager.loadLevel(exit.nextLevelPath, playerEntity)` to perform the actual level transition. Holds a `LevelManager` reference passed in via its constructor. |
| `PlayerDeathSystem` | `IteratingSystem` | all: `PlayerComponent` | Detects the player's health reaching 0: each frame, while an internal `triggered` guard is still `false`, checks `player.health <= 0`; on the first frame this is true, sets `triggered = true` and invokes a `Runnable onDeath` callback passed in via its constructor (fires exactly once per level instance — a fresh `PlayerDeathSystem` is created on every `GameScreen.show()`/level (re)load, so retrying naturally resets the guard). `GameScreen` wires the callback to flip a `gameOverActive` flag and show the Game Over dialog. |
| `CameraSystem` | `EntitySystem` (not iterating; single-purpose) | all: `PlayerComponent`, `TransformComponent` (resolved once in `addedToEngine`) | Room-Based Camera: each frame finds which `RoomState.rooms` rectangle contains the player (`RoomState.findRoomIndexContaining(...)`, updating `RoomState.activeRoomIndex` when found) and clamps the camera's fixed `VIRTUAL_WIDTH`/`VIRTUAL_HEIGHT` viewport within that room's edges, per axis: if the room is no bigger than the viewport on that axis, the camera centers on the room (static, viewport allowed to overshoot the room's edges); otherwise the camera continuously follows the player's position on that axis, clamped so the viewport never crosses the room's edges. The placement logic lives in a `public static snapToRoom(OrthographicCamera, RoomState, float x, float y)` method so `LevelManager` can reuse it verbatim right after a level swap. Replaces the old fixed `VIRTUAL_WIDTH`/`HEIGHT` flip-screen grid entirely. |
| `AnimationSystem` | `IteratingSystem` | all: `AnimationComponent`, `TextureComponent` | If the entity also has `PlayerComponent` + `MovementComponent`, resolves `currentState` from player/movement state (`ATTACKING` > `WALL_CLIMBING` > `JUMPING`/`DOUBLE_JUMPING` > `RUNNING` > `IDLE`) and mirrors the sprite by setting `transform.scale.x = abs(scale.x) * facingDirection`. Resets `stateTime` on state change, otherwise accumulates it, then writes the resolved animation's key frame into `TextureComponent.region`. |
| `TiledMapRenderSystem` | `EntitySystem` (not iterating), `Disposable` | n/a (holds the `TiledMap`/`OrthogonalTiledMapRenderer` directly, no entity family) | Renders the Tiled map's background/collision tile layers each frame via `OrthogonalTiledMapRenderer.setView(camera)` + `render()`. Must be `dispose()`d when the screen changes. `setMap(TiledMap map)` disposes the current `OrthogonalTiledMapRenderer` and builds a new one around the new map — used by `LevelManager` to swap levels without recreating the system (its priority and place in the engine never change). |
| `RenderSystem` | `SortedIteratingSystem` (sorted by a `ZComparator` on `TransformComponent.z`, ascending) | all: `TransformComponent`, `TextureComponent` | Draws every renderable entity via the shared `SpriteBatch`, sized from the texture region times `transform.scale`, centered on `transform.position`, honoring `transform.rotation`. Wraps `batch.begin()/end()` around the sorted iteration in its own `update()` override. |
| `DebugRenderSystem` | `EntitySystem` (not iterating), `Disposable` | all: `TransformComponent`, `CollisionComponent` (resolved once in `addedToEngine`) | Debug-only collision/room visualizer (see AGENTS.md "Debugging"): toggled on/off by SHIFT+D (`Input.Keys.SHIFT_LEFT`/`SHIFT_RIGHT` + `D`, checked every frame regardless of enabled state); while enabled, draws every entity's `CollisionComponent` AABB (lime) at `transform.position` sized by `collision.bounds`, the static map `collisionRects` (yellow), and every `RoomState.rooms` rectangle (cyan, or orange for whichever one is `activeRoomIndex`), via its own `ShapeRenderer` in `ShapeType.Line`. No-op (skips the `ShapeRenderer` block entirely) while disabled. Must run **after** `RenderSystem` so its `ShapeRenderer` begin/end block never overlaps the `SpriteBatch` block. Owns and `dispose()`s its own `ShapeRenderer`. |

### System wiring & priority order (`GameScreen.show()`)
Systems are added to the `PooledEngine` in this priority order (lower runs first each frame); `EnemySystem`/`EnemyShootSystem` share priority `4`, `CollisionSystem`/`EnemyBulletCollisionSystem` share priority `6`, and `MeleeAttackSystem`, `PickupSystem`, `ChestSystem`, `EnemyContactSystem`, `LevelExitSystem`, and `PlayerDeathSystem` share priority `7` — relative order within each shared tier is not meaningful:

1. `PlayerInputSystem` — priority `0`
2. `EnemySystem` — priority `4`
3. `EnemyShootSystem` — priority `4`
4. `MovementSystem` — priority `5`
5. `CollisionSystem` — priority `6`
6. `EnemyBulletCollisionSystem` — priority `6`
7. `MeleeAttackSystem` — priority `7`
8. `PickupSystem` — priority `7`
9. `ChestSystem` — priority `7`
10. `EnemyContactSystem` — priority `7`
11. `LevelExitSystem` — priority `7`
12. `PlayerDeathSystem` — priority `7`
13. `CameraSystem` — priority `8`
14. `AnimationSystem` — priority `10`
15. `TiledMapRenderSystem` — priority `20`
16. `RenderSystem` — priority `30`
17. `DebugRenderSystem` — priority `40`

This ordering matters: input must run before movement/collision resolve it the same frame; enemy AI (patrol + shooting) must set velocity/spawn bullets before `MovementSystem` integrates them; melee/pickup/chest/enemy-contact/enemy-bullet-collision/level-exit/player-death must run after collision-affecting movement but before the camera snaps and animation/rendering read the resulting state; map rendering must happen before entity rendering so entities draw on top. `LevelExitSystem` runs at the same tier since a level transition it triggers must be fully applied (new map, new entities, repositioned player) before `CameraSystem` snaps to the player's (now brand new) room the same frame. `PlayerDeathSystem` runs at the same tier since health decrements from damage systems above it must be visible the same frame it checks `health <= 0`.

### `LevelManager` (`com.axehigh.platformer.map.LevelManager`, not an ECS `Component`/`System`)
Owns in-place level transitions on behalf of `LevelExitSystem`: `loadLevel(String tmxPath, Entity player)` loads a new `MapLoader`, calls `TiledMapRenderSystem.setMap(...)`, clears+refills the shared `collisionRects` array **and** the shared `RoomState.rooms` array in place (so `MovementSystem`/`EnemySystem`/`CollisionSystem`/`EnemyBulletCollisionSystem`/`DebugRenderSystem`/`CameraSystem` all see the new level's walls/rooms immediately, no re-wiring), removes every engine entity except the given player, disposes the old `MapLoader`, respawns the new level's objects via `EntityFactory.spawnObjects(...)` (which assigns each spawned enemy's `roomIndex` from the new `RoomState`), repositions the player's `TransformComponent` to the new map's `playerStart`, resets its transient `MovementComponent` (`velocity`, `grounded`) and `PlayerComponent` flags (`jumpCount`, `isWallClimbing`, `interactPressed`, `nearExit`) while leaving all stat fields (`health`, `coins`, `items`, ...) untouched, and calls `CameraSystem.snapToRoom(...)` to place the camera in the new starting room. `dispose()` disposes whichever `MapLoader` is currently active. Constructed once in `GameScreen.show()` and never rebuilt; the player `Entity`/`PooledEngine` are never destroyed across a level swap, which is why every persistent `PlayerComponent` field survives for free.

## 3. Adding/removing/changing an ECS element — checklist
When you add, remove, or edit a `Component` or `System`:
1. Update the relevant table row(s) above (fields, family, priority, responsibility).
2. If the change affects gameplay-visible mechanics (movement, combat, traversal, enemy behavior, pickups, etc.), also update `resources/docs-ai/gameplay.md` per the `AGENTS.md` "Gameplay Documentation Sync" rule — the two docs are complementary: this file describes the ECS *shape*, `gameplay.md` describes the *mechanics/logic* built on top of it.
3. If a new component needs cross-system lookups, add its `ComponentMapper` to `Mappers`.
4. If a new system is registered, add it to `GameScreen.show()` with an explicit priority constant and update the "System wiring & priority order" list above.
