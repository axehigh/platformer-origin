# Ashley ECS Reference

This document is the **single source of truth for the ECS layer** (`com.axehigh.platformer.ecs`): every `Component` and every `System` currently implemented, what data/behavior it owns, and how systems are wired together at runtime. It is written to be consumed by an AI agent before making any ECS change, so keep it terse, structured, and exhaustive rather than narrative.

> **Maintenance rule:** Any time a `Component` or `System` is added, removed, renamed, or has its fields/behavior/family/priority changed, this file MUST be updated in the same change. This is the ECS counterpart to the `gameplay.md` sync rule in `AGENTS.md`.

---

## 1. Components (`com.axehigh.platformer.ecs.components`)

| Component | Poolable | Fields | Purpose |
|---|---|---|---|
| `TransformComponent` | Yes | `Vector2 position`, `Vector2 scale = (1,1)`, `float rotation`, `float z` | World position, scale (also used to flip sprites via negative `scale.x`), rotation, and z-layer draw order. |
| `TextureComponent` | Yes | `TextureRegion region` | The currently visible texture region for an entity; `null` region is skipped by `RenderSystem`. |
| `AnimationComponent` | No | `ObjectMap<State, Animation<TextureRegion>> animations`, `State currentState/previousState = IDLE`, `float stateTime`, `float blinkTimer` | Per-state animation clips and playback timer. `State` enum: `IDLE, WALKING, RUNNING, JUMPING, DOUBLE_JUMPING, WALL_CLIMBING, ATTACKING, DEATH, HURT`. `blinkTimer` is an elapsed-time accumulator driving the invulnerability blink (sprite-visibility toggling at ~10Hz) once the HURT clip finishes but while `hitInvulnerability` is still active; reset to 0 whenever the player isn't in the blink phase. |
| `MovementComponent` | Yes | `Vector2 velocity`, `Vector2 acceleration`, `float maxSpeedX = 100`, `float maxSpeedY = 400`, `boolean grounded` | Velocity/acceleration and speed clamps consumed by `MovementSystem` (or `PlayerBulletSystem` for bullets). |
| `CollisionComponent` | Yes | `Rectangle bounds`, `Rectangle worldBounds`, `float baseOffsetX/Y`, `float currentOffsetX/Y` | AABB bounding box, relative-sized (positioned each frame from `TransformComponent.position`). `worldBounds` is the absolute map position. `baseOffsetX/Y` is the centering anchor. `currentOffsetX/Y` is the smoothed directional offset. |
| `PlayerComponent` | No | `int health/maxHealth = 3`, `int coins = 0`, `int ammo/maxAmmo = 0/10`, `int facingDirection = 1` (-1 left, 1 right), `int jumpCount`, `int maxJumps = 2`, `boolean isWallClimbing`, `boolean isDead`, `Timer shootCooldown`, `Timer meleeCooldown`, `Timer meleeAttack`, `boolean meleeHasHit`, `ObjectSet<Entity> meleeHitEnemies`, `Timer hitInvulnerability`, `Timer hurtTimer`, `boolean interactPressed`, `boolean nearExit`, `boolean dropRequested`, `boolean onDropTile`, `Timer dropWindow`, `Timer potionCooldown`, `PotionType selectedPotion = HEALING`, `int healingPotions/strengthPotions/speedPotions/invulnerabilityPotions = 0`, `boolean inAir`, `float maxAirHeight`, `boolean squashActive`, `boolean squashIsStretch`, `float squashAmount`, `float squashBaseX`, `float squashBaseY` | Flag + state component for the single player entity: health, currency, ammo, traversal (double jump, wall climb, drop-through platforms), combat (melee/ranged) state, the post-hit invulnerability grace period, the short hit-stun window (`hurtTimer` — input lock + HURT animation window, started alongside `hitInvulnerability` by `PlayerDamageResolver`), the death flag (`isDead` — set by `PlayerDeathSystem` the frame `health` reaches 0, cleared on revival/Continue, drives the death animation + full input/velocity freeze), the exit-gate interact flow (`interactPressed` is a one-shot per-frame flag set by `PlayerInputSystem`, `nearExit` drives the touch UI prompt and is set by `LevelExitSystem`), the drop-through-platform flow (`dropRequested` is a one-shot per-frame flag set by `PlayerInputSystem` on `S`/`DOWN`/the `v` touch button, which starts `dropWindow`; while `dropWindow` (a ~0.25s `Timer`) is active `MovementSystem` lets the player fall through one-way platforms, and `onDropTile` — set by `MovementSystem` while the player is grounded on a one-way platform — drives the contextual `v` touch button), the airborne-tracking fields (`inAir` = true from the frame the player leaves the ground until the next grounded frame, `maxAirHeight` = highest feet position reached while airborne — both maintained by `MovementSystem`/`MovingPlatformSystem` and consumed by `MovementSystem.onLanding(...)` to gate the one-tile landing-dust rule), and the landing squash-and-stretch pulse fields (`squashActive`, `squashIsStretch` — jump stretch currently unused, `squashAmount`, `squashBaseX/Y` — driven by `SquashSystem`, see its row below). For a fresh game the player starts with `GameConstants.PlayerStartBullet` ammo (default `5`, set by `PlayerFactory.createPlayer(...)`); a loaded save overrides it via `SaveData.applyTo(...)`. All of these survive a `LevelManager.loadLevel(...)` swap untouched except `interactPressed`/`nearExit`/`dropRequested`/`onDropTile`/`dropWindow`/`inAir`/`maxAirHeight`/the squash fields, which are explicitly reset (along with transient movement state) since it's literally the same component instance kept alive across levels. The potion inventory fields (`healingPotions`/`strengthPotions`/`speedPotions`/`invulnerabilityPotions`, capped at `GameConstants.POTION_CAP`) are stat fields filled by `PickupSystem` and survive level swaps untouched; `selectedPotion` is the potion type the "use potion" action currently targets (advanced by `PlayerInputSystem`'s cycle input) and also survives, while `potionCooldown` is a short drink-spam window (`GameConstants.POTION_USE_COOLDOWN`) started by `PlayerInputSystem` on every successful drink. |
| `BuffComponent` | No | `Timer strength`, `Timer speed`, `Timer invulnerability`, `boolean speedApplied = false`, `float speedBaseMaxSpeedX = GameConstants.MaxSpeedX` | Timed consumable buffs on the player (from Strength / Speed / Invulnerability potions). Each buff is a `Timer` ticked by `BuffSystem`; `startStrength()/startSpeed()/startInvulnerability()` refresh the full duration on reuse (no stacking), and the `is*Active()` predicates are read by the effect consumers (`MeleeAttackSystem` doubles `player.swordDamage` while `strength` is active; `PlayerDamageResolver` ignores all damage while `invulnerability` is active). The speed buff is special: `BuffSystem` scales `MovementComponent.maxSpeedX` by `GameConstants.SPEED_MULTIPLIER` while `speed` is active, caching the pre-buff max in `speedBaseMaxSpeedX` (flipped via `speedApplied`) so a level swap that resets `maxSpeedX` can't clobber an active buff and the original value is restored on expiry; it also sets `player.maxJumps = 3` for triple jump (restored to `2` on expiry). Attached to the player by `EntityFactory.createPlayer(...)`; potions are consumed by `PlayerInputSystem` (the **C** quick-drink) and the hotbar `InventoryBarStage` (tap a slot; the game keeps running while it's open), both routing through the shared `PotionEffects` helper. |
| `BulletComponent` | Yes | `float damage`, `float lifetime`, `float elapsed` | Marks a spawned projectile entity; despawns once `lifetime` elapses without a hit. `damage` is `0` for enemy-fired bullets (see `EnemyBulletComponent`), since those damage the player via the flat contact-damage rule, not HP damage. `elapsed` tracks time since spawn, used by `PlayerBulletSystem` to give freshly-spawned bullets a short wall-collision grace window. |
| `EnemyComponent` | No | `float health = 10`, `float maxHealth = 10`, `float speed = 20`, `int direction = 1` (1=right, -1=left), `float patrolRange = 64`, `float originX`, `AiMode aiMode = PATROL` (enum: `PATROL` / `SIDE_TO_SIDE`), `Timer turnPause`, `Timer hitStun`, `Timer postHitIdle`, `boolean isDead = false`, `Timer deathTimer`, `boolean deathCoinsSpawned = false`, `int roomIndex = -1`, `boolean wasFrozen = false` | Damageable enemy with patrol movement resolved by `EnemySystem` (direction/velocity are stored here so the system stays stateless between entities); damage is applied externally by `PlayerBulletSystem`/`MeleeAttackSystem`, which also start `hitStun` (a post-hit grace period during which patrol AI pauses and further hits are ignored). When health reaches zero, `isDead` is set to `true` and `deathTimer` is started at the `DEATH` animation duration **plus** `EnemyDamageResolver.DEATH_FLASH_DURATION` (`0.8s` blink window); `EnemySystem` removes the entity once it elapses. `maxHealth` is the starting/full health, set alongside `health` by `EntityFactory`, and sizes the death coin drop (`floor(maxHealth / 5)` coins, spawned immediately on the kill — first dead frame — guarded by `deathCoinsSpawned` so it fires exactly once). `aiMode` selects the patrol behavior: `PATROL` turns at `patrolRange`/`originX` (plus walls/ledges/hazards), `SIDE_TO_SIDE` skips the range bound and turns on walls/ledges/hazards only (set from the Tiled `aiMode` property; a `SIDE_TO_SIDE` flyer flies straight). `turnPause` is a short stand-still `EnemySystem` starts after every turn-around. `roomIndex` is the index into `RoomState.rooms` of the Room rectangle this enemy was spawned inside of (set by `EntityFactory` from the spawn point's containment), or `-1` if it wasn't inside any known room (always active); `EnemySystem`/`EnemyShootSystem` freeze this enemy's patrol/firing while `roomIndex` doesn't match `RoomState.activeRoomIndex`; `wasFrozen` is set by `EnemySystem` while that freeze is in effect and consumed on the first active frame to skip the wall-block turn check (so re-entering a room doesn't flip every unfrozen enemy in unison). At spawn `EntityFactory` randomizes `direction` (50/50) and jitters `speed` ±15% so same-room enemies don't patrol in lockstep. After `hitStun` ends, `postHitIdle` is used to pause the enemy for a brief period before resuming patrol. |
| `FlyingEnemyComponent` | No | `float bobAmplitude = 8`, `float bobFrequency = π` (rad/s), `float bobTime` | Layered on top of `EnemyComponent` to tag an enemy as immune to gravity; checked by `MovementSystem`, which skips the gravity/wall-slide velocity-Y update entirely when present, so the entity hovers at whatever height it's at (no bobbing without a horizontal velocity source, since gravity never pulls it back). `EnemySystem` also drives a time-based vertical bob wave into `movement.velocity.y` from `bobAmplitude`/`bobFrequency`/`bobTime` every non-stunned frame, so the flyer flaps up/down around its spawn height while patrolling; `bobTime` freezes whenever patrol AI is paused (hit-stun); at spawn `bobTime` is seeded to a random phase so multiple flyers don't flap in unison. Horizontal patrol logic needs no changes: a flying enemy is never `grounded`, so it turns around purely via `patrolRange`/`originX`. |
| `EnemyShooterComponent` | No | `Timer shootCooldown`, `float shootInterval = 5` | Layered on top of `EnemyComponent` to tag an enemy as able to fire a bullet periodically; resolved by `EnemyShootSystem`, which additionally only lets a ready shooter actually fire while its `EnemyComponent.roomIndex` is the currently active Room (see `EnemyShootSystem` row below). The enemy still patrols normally (driven by `EnemySystem`, which already matches its family). |
| `EnemyAttackComponent` | No | `AttackType attackType = MELEE` (enum: `MELEE`), `float attackInterval = 2.0f`, `Timer attackCooldown`, `float windUpDuration = 0.4f`, `Timer windUp`, `boolean isAttacking = false`, `float attackRange = 24f`, `float detectionHeight = 20f`, `float strikeWindow = 0.2f`, `Timer strike`, `float attackDamage = 1f`, `float recoveryDuration = 0.5f`, `Timer recovery` | Layered on top of `EnemyComponent` to give an enemy an active melee attack. Resolved by `EnemyAttackSystem`. The `attackCooldown` timer prevents rapid-fire attacks; `windUp` provides a visible telegraph before damage. `attackRange` is the front strike-commit distance (in world units, before `unitScale`): a rectangle `attackRange × unitScale` wide, adjacent to the enemy's facing edge, must overlap the player before a strike commits. `detectionHeight` (default `20` = 1.25 tiles) sizes the centered, omni-directional live detection box (`attackRange × 3` per horizontal side, `detectionHeight` tall total, both × `unitScale`); a detected player is chased by `EnemySystem`. `strike`/`strikeWindow` (`0.2s`) are the live "blade out" window after the wind-up: while the window is active the strike hitbox (enemy collision width × height, in front of the enemy) can deal damage and is exposed via `EnemyAttackSystem.getActiveStrikeBounds()`. There is no awareness latch — detection is strictly live. `recovery` is the post-strike "wind down": started when a strike resolves (hit or whiff) for `recoveryDuration`, during which `EnemySystem` holds the enemy stationary, facing locked, and `EnemyAttackSystem` refuses a new trigger — so a swing never lurches into a turn-around right after it completes; the frame the recovery ends also skips the wall-block turn check once (`resumedFromAttack = wasRecovering` in `EnemySystem`), so the recovery-zeroed velocity isn't misread as a wall collision. Tiled properties: `attackType`, `attackInterval`, `attackRange` (legacy alias `meleeRange`), `windUpDuration`. Non-shooter enemies default to melee; shooters do not get this component unless explicitly set. |
| `EnemyBulletComponent` | Yes | *(none — empty marker)* | Tags a bullet entity as enemy-fired (as opposed to the player's own bullets), attached alongside `BulletComponent` by `EnemyShootSystem`. `PlayerBulletSystem` excludes it; `EnemyBulletCollisionSystem` processes it instead. |
| `CoinPickupComponent` | No | `int amount = 1` | Marker for a coin pickup; grants `amount` to `PlayerComponent.coins` (uncapped) on pickup. The coin entity itself is an animated atlas sprite (`Coin_01..06` regions, `IDLE` spin) built by `EntityFactory` — the Tiled tile sprite is never used for collectible coins. |
| `DaggerPickupComponent` | No | `int amount = 5` | Marker for a dagger pickup; grants `amount` to `PlayerComponent.ammo`, capped at `maxAmmo`. |
| `ChestComponent` | No | `boolean opened = false`, `Timer disappearTimer`, `boolean coinsDropped = false`, `PotionType potionType = null` | Tracks a chest's open state after being melee-struck: on open it swaps its atlas sprite from `Chest_01_Locked` to `Chest_01_Unlocked` and starts `disappearTimer` (~0.3s); once that completes, `ChestSystem` pops loot exactly once and sets `coinsDropped = true`. If `potionType` is non-null (set from the `potionType` Tiled object property), a single potion pickup is spawned instead of the coin burst. The chest entity **stays** in the world as the opened container (it is never removed). |
| `PoppedItemComponent` | No | *(none — empty marker)* | Tags a pickup entity (currently only chest- and enemy-dropped coins) that was launched with an initial `MovementComponent.velocity`; checked by `MovementSystem`, which zeroes `velocity.x` the moment `grounded` first becomes true so it comes to a dead stop on landing instead of sliding (there's no ground friction elsewhere). |
| `LevelExitComponent` | No | `String nextLevelPath = ""`, `float fadeProgress = 0`, `boolean isFinalLevel = false` | Marks an exit-gate entity as an actual level-transition trigger (as opposed to a purely decorative gate); added by `EntityFactory.createExitGate(...)` only when the gate's Tiled object has a `nextLevel` custom property **or** is flagged `isFinal`. The gate entity is **logic-only** — it draws no sprite (the door's art/decoration is painted by the level designer in the map layers) and sizes its `CollisionComponent.bounds` from the Tiled object rectangle. Read and updated by `LevelExitSystem`, which drives the proximity glow fade and hands `nextLevelPath` to `LevelManager.loadLevel(...)`. When `isFinalLevel` is set (from the gate's `isFinal=true` Tiled property), interacting with the gate triggers the victory callback instead of loading the next level. |
| `MovingPlatformComponent` | No | `float baseX/baseY`, `float amplitudeX/amplitudeY`, `float speed = 1` (rad/s), `float phase`, `float angle`, `int roomIndex = -1` | Tags a scripted moving platform (Tiled object of type `platform`). The platform oscillates around its spawn/base rectangle as `base + amplitude * sin(angle + phase)` per axis, driven entirely by `MovingPlatformSystem` — there is deliberately **no** `MovementComponent`, so gravity never applies and the scripted motion is the only movement. `speed` is the angular frequency in rad/s; `phase` desyncs multiple platforms. `roomIndex` mirrors `EnemyComponent.roomIndex`: the index into `RoomState.rooms` of the Room the platform's spawn point sits in, or `-1` for always-active; the platform only moves while its owning room is the active one (the player can still land on a frozen platform). |
| `ParticleComponent` | Yes | `ParticleEffect effect`, `boolean isDead = false`, `float delay = 0`, `boolean started = false`, `float scale = 1`, `float lifeTimer = 0`, `float maxLifetime = 4` | Marks a one-shot visual particle-effect entity, created by `ParticleHelper.spawnParticle(...)` as a `new ParticleEffect(template)` clone (shares the template's textures; the clone does **not** own them, so it is never `dispose()`d). `started` becomes `true` once the effect is started (after `delay` elapses), `isDead` is set by `ParticleSystem` when the effect completes, and `effect`/`delay`/`scale` drive the spawn. `lifeTimer` counts the running seconds and `maxLifetime` is a hard cap: `ParticleSystem` force-removes the entity once `lifeTimer >= maxLifetime` even if the effect never completes, so a looping/runaway effect can't linger (coin sparkles use a short `1.5s` cap; enemy hit-sparks and sword-clank wall sparks use `1.0s` via `EnemyDamageResolver.HIT_SPARK_MAX_LIFETIME`). `reset()` (pooled) calls `effect.reset()` then nulls it. Consumed by `ParticleSystem`. |
| `LightComponent` | Yes | `float radius = 96`, `Color color = (1, 0.85, 0.6, 1)`, `float baseAlpha = 0.85`, `float flickerAmplitude = 0.15`, `float flickerSpeed = 6`, `float phase = 0`, `Vector2 offset = (0,0)` | Marks a decorative glow source, drawn as a soft additive halo by `LightRenderSystem`. `radius` is the halo radius in world units (before flicker scaling), `color` tints the white-gradient glow texture, `baseAlpha` is the average opacity, `flickerAmplitude`/`flickerSpeed` drive the per-light sine-based pulse, and `phase` desyncs multiple lights so torches don't pulse in sync. `offset` is the halo center in world units relative to the entity's `TransformComponent.position` (torches set it to the flame at the sprite's top). Attached to torch decorations (see `EntityFactory.createTorch`), active player potion buffs (see `BuffSystem`), and interactable exit doors within player proximity (see `LevelExitSystem`), with an optional `lightRadius` Tiled custom property overriding `radius` on map lights. Defaults are the **large, bright torch** halo (`96` radius — doubled from the older `48` — with a `0.85` alpha and warm-white `(1, 0.85, 0.6)` tint). |
| `TrapComponent` | Yes | `TrapType type` (enum: `ACID_DROP_SPAWNER`, `ACID_DROP`, `ACID_POOL`, `FLAME`), `TrapDirection spawnDirection/flameDirection` (enum: `UP`, `DOWN`, `LEFT`, `RIGHT`), `int roomIndex = -1`, `float spawnInterval = 2.0`, `float projectileSpeed = 200`, `float damage = 1`, `float spawnOffsetX/spawnOffsetY = 0` (world-space drop origin offset from the spawner's tile corner, from the acid tile's collision-editor point), `Timer spawnTimer`, `float dropDamage = 1`, `float lifetime = 3.0`, `Timer lifetimeTimer`, `Timer spawnGrace` (short grace window started when a drop releases, during which wall-culling is skipped so it can clear the wall cell it spawned on), `float dropVelocityX/dropVelocityY` (current xy velocity of a falling drop), `float dropAccel` (signed acceleration applied along the drop's travel direction for a dripping feel), `float dripBuild = 0.15` + `Timer dripBuildTimer` (brief hang at the spawn point before the drop releases), `float poolDuration = 1.5` + `Timer poolTimer` (acid-pool lifetime), `float minScale = 0.2`, `float maxScale = 1.0`, `float pulseSpeed = 2.0`, `float currentScale = 0.2`, `float flameHeight = 48`, `float flameWidth = 24`, `boolean isFlaming = false`, `Timer flameTimer`, `Timer cooldownTimer`, `float flameDuration = 2.0`, `float cooldownDuration = 1.5` | Marks an entity as a trap: acid/lava drop spawner, falling drop, **landed acid pool**, or flame hazard. Different fields are used depending on `TrapType`. Spawner fields control drip interval and projectile speed. Drop fields track lifetime, run direction/velocity, drip-build hang, and gravity acceleration. Pool fields (`poolDuration`/`poolTimer`) control how long a landed acid pool lingers. Flame fields control the pulse cycle (scale oscillation between min/max), cooldown, and directional orientation. All trap types are room-gated via `roomIndex`. |

### `Mappers` (`com.axehigh.platformer.ecs.components.Mappers`)
Central holder of shared `ComponentMapper<T>` instances (one static field per component above: `TRANSFORM`, `TEXTURE`, `ANIMATION`, `MOVEMENT`, `COLLISION`, `PLAYER`, `BUFF`, `BULLET`, `ENEMY_BULLET`, `ENEMY`, `FLYING`, `ENEMY_SHOOTER`, `ENEMY_ATTACK`, `DAGGER_PICKUP`, `COIN_PICKUP`, `POTION_PICKUP`, `CHEST`, `POPPED_ITEM`, `LEVEL_EXIT`, `MOVING_PLATFORM`, `PARTICLE`, `LIGHT`, `TRAP`). **Every system must read/write components through these mappers** instead of creating new `ComponentMapper.getFor(...)` calls. Adding a new component requires adding its mapper here.

### `RoomState` (`com.axehigh.platformer.map.RoomState`, not an ECS `Component`)
A plain shared-state holder (same sharing pattern as the shared `collisionRects` array, not a `Component`/`System`) built from a map's **"Rooms" object layer**: `Array<Room> rooms` (every room rectangle from that layer, parsed by `MapLoader.getRooms()`) and `int activeRoomIndex = -1` (index into `rooms` of whichever one currently contains the player). Exposes `findRoomIndexContaining(float x, float y)`, a linear scan returning the first room rectangle containing that point, or `-1`. A single instance is created once in `GameScreen.show()`, passed to `CameraSystem`, `EnemySystem`, `EnemyShootSystem`, `EnemyAttackSystem`, `MovingPlatformSystem`, `DebugRenderSystem`, `EntityFactory.spawnObjects(...)`, and `LevelManager`; `LevelManager.loadLevel(...)` clears+refills `rooms` in place on every level swap, so every holder sees the new level's rooms immediately, no re-wiring needed — identical in spirit to how `collisionRects` is shared.

### `Room` (`com.axehigh.platformer.map.Room`, not an ECS `Component`)
A plain `Rectangle` subclass carrying one extra field — the camera-mode override. `Array<Room>` is what `RoomState.rooms` actually holds, so any consumer reading a room as a plain `Rectangle` (e.g. `DebugRenderSystem`, `CameraSystem`) keeps working unchanged. Field: `Mode mode` (`AUTO`, `FLIP`, or `SCROLL`), parsed by `MapLoader.getRooms()` from the room's optional `camera` Tiled custom property (`"flip"`/`"scroll"`; anything else = `AUTO`). `CameraSystem` resolves the effective mode **per axis**: `AUTO` infers from size (room bigger than the viewport on an axis → scroll, otherwise → static center), `FLIP` forces static room-centered framing, `SCROLL` forces dead-zone scrolling (still falling back to centering when the room is smaller than the viewport, since there is nothing to scroll).

### `SecretRoom` (`com.axehigh.platformer.map.SecretRoom`, not an ECS `Component`)
Plain data holder for one **hidden** secret room (see `map-design-for-tiled.md` §3.5), grouped by `MapLoader.getSecretRooms()` from three map artifacts linked by a shared room name: `String name` (matched against the `Rooms` rect's object name, the secret wall tile's `secretRoom` property, and the deferred markers' `secretRoom` object property), `Room room` (the matching `Rooms` rect, `null` if absent), `Array<Rectangle> walls` (the `secret=true` + `secretRoom` collision-layer wall rects protecting this room), `Array<Rectangle> veilCells` (the `secret_hide`-layer cells (as world-space rects) blanked on reveal), `MapObjects deferredObjects` (the loot/enemy markers partitioned OUT of the normal `objects`/`enemies` spawn layers), and `boolean revealed` (idempotency gate so breaking two walls of the same room reveals + spawns exactly once).

### `SecretRoomRevealer` (`com.axehigh.platformer.map.SecretRoomRevealer`, not an ECS `Component`/`System`)
Engine-side service that makes a hidden secret room appear. Constructed once in `GameScreen.show()` with the `PooledEngine`, `EntityFactory`, and shared `RoomState`; `LevelManager.loadLevel(...)` re-seeds it on every level swap via `setRooms(Array<SecretRoom>)` + `setHideLayer(TiledMapTileLayer)` (null-safe — plain maps without hidden rooms keep it a no-op). `reveal(String roomName)` (idempotent, gated by `SecretRoom.revealed`) blanks every veil cell in the `secret_hide` layer (`cell.setTile(null)` — purely visual; collision stays solely in the `collision` layer), spawns the room's deferred markers via `EntityFactory.spawnObjects(engine, room.deferredObjects, roomState)` exactly once, and spawns a `ParticleHelper.spawnSmallSmoke` puff at each veil-cell center. Called by `MeleeAttackSystem.breakSecretWall(...)` when the struck wall's tile carries a `secretRoom` property; `isRevealed(String)` exposes the per-room gate.

### `Timer` (`com.axehigh.platformer.util.Timer`)
A plain (non-`Component`, non-`Poolable`) helper class embedded as a field inside components that need a countdown — not an Ashley concept, just a reusable value holder. API: `start(float duration)`, `update(float deltaTime)` (clamped at 0, no-op once done), `isActive()`, `isDone()`, `getRemaining()`, `reset()`. Used by `PlayerComponent` (`shootCooldown`, `meleeCooldown`, `meleeAttack`, `hitInvulnerability`, `hurtTimer`, `dropWindow`, `potionCooldown`), `BuffComponent` (`strength`, `speed`, `invulnerability`), `ChestComponent` (`disappearTimer`), `EnemyComponent` (`hitStun`), `EnemyShooterComponent` (`shootCooldown`), and `EnemyAttackComponent` (`attackCooldown`, `windUp`, `strike`); **any new cooldown/countdown/grace-period field should use `Timer` instead of a raw `float`.**

### `FeatureFlags` (`com.axehigh.platformer.util.FeatureFlags`, not an ECS `Component`)
A session-wide static holder for developer feature flags (same spirit as `RoomState`/`collisionRects` — shared runtime state, not an Ashley concept), mirroring the static-toggle pattern of `DebugRenderSystem.debugEnabled` but persistence-backed. Statics are seeded once from `GamePreferences` on first read and survive level reloads within a session; setters also persist them across app restarts. All access is safe without a running `Gdx` application (headless tests): reads fall back to the documented default, writes update the static without persisting. Current flags: `wallClimbingEnabled` (default `true`) — gating the wall-climb mechanic in `MovementSystem` (wall-slide gravity + the `jumpCount = 1` wall-jump latch; when OFF the player never latches and falls at full gravity), toggled live from the pause dialog's "Wall Climb" button. This is the first step towards replacing wall-climb with ladder/vine traversal. `squashEnabled` (default `false`) — gating the player landing squash pulse. `selectLevelEnabled` (default `true`) — gating whether the main menu shows its Select Level entry (checked when `MainMenuScreen.show()` builds its UI).

### `EnemyDamageResolver` (`com.axehigh.platformer.ecs.systems.EnemyDamageResolver`)
A package-private static helper (not a `Component`/`System`) shared by `PlayerBulletSystem` (bullet hits) and `MeleeAttackSystem` (melee hits) so both damage sources apply enemy hit-reaction identically. `applyHit(Entity enemyEntity, EnemyComponent enemy, MovementComponent movement, float damage, int knockbackDirection, boolean isFlying, float unitScale, PooledEngine engine)`: if `enemy.isDead` or `enemy.hitStun.isActive()`, the hit is fully ignored (returns `false`); otherwise subtracts `damage` from `enemy.health`. If health reaches 0, sets `enemy.isDead = true`, zeroes `movement.velocity`, starts `enemy.deathTimer` based on the `DEATH` animation duration **plus** the package-visible `DEATH_FLASH_DURATION` (`0.8s` — the corpse's post-animation blink window, driven by `AnimationSystem`), and returns `true`. Otherwise, sets `movement.velocity.x` to a knockback pop (`90` u/s horizontal away from the attacker) and, unless `isFlying`, a `140` u/s vertical hop, starts `enemy.hitStun` for a duration matching the `HURT` animation (min `0.3s`), spawns a one-shot spark burst at the enemy's center when an engine is supplied (`GlobalParticles.SPARKS`, scale `1.2`, hard `maxLifetime` `1.0s` — `HIT_SPARK_SCALE`/`HIT_SPARK_MAX_LIFETIME`, package-visible and reused by `MeleeAttackSystem`'s wall clank), and returns `false`.

### `PlayerDamageResolver` (`com.axehigh.platformer.ecs.systems.PlayerDamageResolver`)
The player-side counterpart of `EnemyDamageResolver`: a package-private static helper shared by `EnemyContactSystem` (touch), `EnemyBulletCollisionSystem` (enemy bullet), `HazardSystem` (hazard tiles), and `EnemyAttackSystem` (melee attack) so all player damage sources apply the same hit-reaction. `applyHit(Entity playerEntity, PlayerComponent player, MovementComponent movement, int knockbackDirection, float unitScale)`: if `player.isDead` or `player.hitInvulnerability.isActive()` — or the player's Invulnerability potion buff is active (`BuffComponent.invulnerability`, looked up defensively via the `BUFF` mapper) — the hit is fully ignored (returns `false`); otherwise decrements `player.health` (clamped at 0), sets `movement.velocity.x` to a small knockback push (`60` u/s horizontal, direction given by `knockbackDirection` — no vertical pop), starts `player.hurtTimer` for a duration matching the `HURT` animation (min `0.3s`, so the clip visibly plays once), and starts `player.hitInvulnerability` for `2.0s`. Returns `true` if the hit applied. `applyHitWithoutKnockback(Entity playerEntity, PlayerComponent player)`: the **no-knockback** variant used by `HazardSystem` — same guard (including the buff check), health decrement, `hurtTimer`, and `hitInvulnerability` bookkeeping, but the player's `MovementComponent.velocity` is left completely untouched, so a hazard touch damages without shoving the player (appropriate for static hazard tiles where there's no meaningful "attacker direction"). Both funnel through a private `applyStunAndGrace(...)` for the shared stun/grace bookkeeping. `HIT_INVULNERABILITY_DURATION = 2.0f` is the single source of truth for the grace period all callers share.

### System wiring & priority order (`ecs.GameSystems`)
All gameplay systems are constructed and registered with the `PooledEngine` by the `GameSystems` installer (one instance built in `GameScreen.show()`), not by the screen itself; `GameScreen` keeps handles only on the bundle's exposed members (`playerInputSystem`, `tiledMapRenderSystem`, `debugRenderSystem`, `lightRenderSystem`, `cameraSystem`, `chestSystem`, `levelManager`). Systems are added to the `PooledEngine` in this priority order (lower runs first each frame); `EnemySystem`/`EnemyShootSystem`/`BuffSystem`/`TrapSystem` share priority `4`, `CollisionBoundsSystem`/`DespawnSystem`/`MovingPlatformSystem` share priority `6` (`DespawnSystem` runs after `CollisionBoundsSystem` and `MovingPlatformSystem` is added **after** `DespawnSystem`, and Ashley's sort is stable, so within the tier bounds refresh runs first, then despawn, then platform carry), `PlayerBulletSystem`/`EnemyBulletCollisionSystem` share priority `7`, and `MeleeAttackSystem`, `SfxSystem`, `PickupSystem`, `ChestSystem`, `EnemyContactSystem`, `EnemyAttackSystem`, `HazardSystem`, `TrapContactSystem`, `LevelExitSystem`, and `PlayerDeathSystem` share priority `8` — relative order within each shared tier is not meaningful except for the noted bounds→despawn→platform order:

1. `PlayerInputSystem` — priority `0`
2. `MusicSystem` — priority `1`
3. `EnemySystem` — priority `4`
4. `EnemyShootSystem` — priority `4`
5. `BuffSystem` — priority `4`
6. `TrapSystem` — priority `4`
7. `MovementSystem` — priority `5`
8. `CollisionBoundsSystem` — priority `6`
9. `DespawnSystem` — priority `6`
10. `MovingPlatformSystem` — priority `6`
11. `PlayerBulletSystem` — priority `7`
12. `EnemyBulletCollisionSystem` — priority `7`
13. `MeleeAttackSystem` — priority `8`
14. `SfxSystem` — priority `8`
15. `PickupSystem` — priority `8`
16. `ChestSystem` — priority `8`
17. `EnemyContactSystem` — priority `8`
18. `EnemyAttackSystem` — priority `8`
19. `HazardSystem` — priority `8`
20. `TrapContactSystem` — priority `8`
21. `LevelExitSystem` — priority `8`
22. `PlayerDeathSystem` — priority `8`
23. `CameraSystem` — priority `9`
24. `AnimationSystem` — priority `10`
25. `ParallaxBackgroundSystem` — priority `19`
26. `TiledMapRenderSystem` — priority `20`
27. `SquashSystem` — priority `25`
28. `RenderSystem` — priority `30`
29. `ParticleSystem` — priority `35`
30. `LightRenderSystem` — priority `36`
31. `DebugRenderSystem` — priority `40`

This ordering matters: input must run before movement/collision resolve it the same frame; `MusicSystem` runs right after input purely so the in-game track is started as early as possible in the frame (its behavior is frame-order-independent); enemy AI (patrol + shooting) must set velocity/spawn bullets before `MovementSystem` integrates them; `BuffSystem` runs in the enemy-AI tier so the speed buff's `maxSpeedX` multiplier is re-asserted before `MovementSystem` clamps horizontal velocity the same frame; `DespawnSystem` runs at the `CollisionBoundsSystem` tier (priority `6`) so off-screen fallen entities are removed after movement resolves but before `MovingPlatformSystem` or `CameraSystem` read positions; `MovingPlatformSystem` must run after `MovementSystem` (the player's own gravity/collision for the frame must already be resolved before a platform can carry/snap it) and after `CollisionBoundsSystem` (platform `worldBounds` must be current when the landing band is checked) but before `CameraSystem`/`AnimationSystem`/rendering read the resulting state; melee/pickup/chest/enemy-contact/**enemy-attack**/hazard/level-exit/player-death must run after collision-affecting movement but before the camera snaps and animation/rendering read the resulting state (`SfxSystem` sits in this tier because `PickupSystem` calls `playCoin()` on it and `MeleeAttackSystem` calls `playWallBreak()` on it; `HazardSystem` sits here so the shared `hitInvulnerability` grace it ticks/consumes is settled after `MovementSystem` has already resolved this frame's one-way/solid collisions, and before `AnimationSystem` renders the hurt blink; `EnemyAttackSystem` runs in the same tier as `EnemyContactSystem` so both damage sources tick the shared `hitInvulnerability`/`hurtTimer` and apply damage in the same priority band); map rendering must happen before entity rendering so entities draw on top; `SquashSystem` runs after `AnimationSystem` (the current animation frame is what the pulse scales) and after map rendering but before `RenderSystem` draws the scaled sprite. `LevelExitSystem` runs at the same tier since a level transition it triggers must be fully applied (new map, new entities, repositioned player) before `CameraSystem` snaps to the player's (now brand new) room the same frame. `PlayerDeathSystem` runs at the same tier since health decrements from damage systems above it must be visible the same frame it checks `health <= 0`.

### `LevelManager` (`com.axehigh.platformer.map.LevelManager`, not an ECS `Component`/`System`)
Owns in-place level transitions on behalf of `LevelExitSystem`: `loadLevel(String tmxPath, Entity player)` loads a new `MapLoader`, calls `TiledMapRenderSystem.setMap(...)`, clears+refills the shared `collisionRects`, `oneWayRects`, `hazardRects`, and `secretRects` arrays **and** the shared `RoomState.rooms` array in place (so `MovementSystem`/`EnemySystem`/`PlayerBulletSystem`/`EnemyBulletCollisionSystem`/`HazardSystem`/`MeleeAttackSystem`/`DebugRenderSystem`/`CameraSystem` all see the new level's walls/one-way platforms/hazards/secret walls/rooms immediately, no re-wiring), pushes the new map's collision tile layer into `MeleeAttackSystem.setCollisionLayer(...)` so secret-wall cells are blanked correctly, re-seeds the injected `SecretRoomRevealer` with `setRooms(mapLoader.getSecretRooms())` + `setHideLayer(mapLoader.getSecretHideLayer())` so the new level's hidden rooms re-arm, removes every engine entity except the given player, disposes the old `MapLoader`, respawns the new level's objects via `EntityFactory.spawnObjects(...)` (which assigns each spawned enemy's and moving platform's `roomIndex` from the new `RoomState`), repositions the player's `TransformComponent` to the new map's `playerStart`, resets its transient `MovementComponent` (`velocity`, `grounded`) and `PlayerComponent` flags (`jumpCount`, `isWallClimbing`, `interactPressed`, `nearExit`, `dropRequested`, `onDropTile`, `dropWindow`, plus the airborne/squash transients `inAir`, `maxAirHeight`, `squashActive`, `squashAmount`) while leaving all stat fields (`health`, `coins`, `ammo`, ...) untouched, pushes the new map's `unitScale` into every scale-dependent system including `MovingPlatformSystem.setUnitScale(newScale)` (so the landing-dust 1-tile height gate matches the new map), and calls `CameraSystem.snapToRoom(..., bandZoom)` to place the camera in the new starting room (the `bandZoom` flag is forwarded from `GameScreen.applyLayoutMode()` via `setBandZoom(boolean)`). `dispose()` disposes whichever `MapLoader` is currently active. Constructed once in `GameScreen.show()` (constructor takes the shared `RoomState`, `collisionRects`, `oneWayRects`, `hazardRects`, `secretRects`, `EntityFactory`, `TiledMapRenderSystem`, `MeleeAttackSystem`, `MovingPlatformSystem`, `CameraSystem`, and the `SecretRoomRevealer`) and never rebuilt; the player `Entity`/`PooledEngine` are never destroyed across a level swap, which is why every persistent `PlayerComponent` field survives for free.

## 3. Adding/removing/changing an ECS element — checklist
When you add, remove, or edit a `Component` or `System`:
