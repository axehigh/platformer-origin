# Ashley ECS Reference

This document is the **single source of truth for the ECS layer** (`com.axehigh.platformer.ecs`): every `Component` and every `System` currently implemented, what data/behavior it owns, and how systems are wired together at runtime. It is written to be consumed by an AI agent before making any ECS change, so keep it terse, structured, and exhaustive rather than narrative.

> **Maintenance rule:** Any time a `Component` or `System` is added, removed, renamed, or has its fields/behavior/family/priority changed, this file MUST be updated in the same change. This is the ECS counterpart to the `gameplay.md` sync rule in `AGENTS.md`.

---

## 1. Components (`com.axehigh.platformer.ecs.components`)

| Component | Poolable | Fields | Purpose |
|---|---|---|---|
| `TransformComponent` | Yes | `Vector2 position`, `Vector2 scale = (1,1)`, `float rotation`, `float z` | World position, scale (also used to flip sprites via negative `scale.x`), rotation, and z-layer draw order. |
| `TextureComponent` | Yes | `TextureRegion region` | The currently visible texture region for an entity; `null` region is skipped by `RenderSystem`. |
| `AnimationComponent` | No | `ObjectMap<State, Animation<TextureRegion>> animations`, `State currentState/previousState = IDLE`, `float stateTime`, `float blinkTimer` | Per-state animation clips and playback timer. `State` enum: `IDLE, WALKING, RUNNING, JUMPING, DOUBLE_JUMPING, WALL_CLIMBING, ATTACKING, DEATH, HURT`. `blinkTimer` is an elapsed-time accumulator driving the invulnerability blink (sprite-visibility toggling at ~10Hz) once the HURT clip finishes but while `hitInvulnerability` is still active; reset to 0 whenever the player isn't in the blink phase. |
| `MovementComponent` | Yes | `Vector2 velocity`, `Vector2 acceleration`, `float maxSpeedX = 100`, `float maxSpeedY = 400`, `boolean grounded` | Velocity/acceleration and speed clamps consumed by `MovementSystem` (or `CollisionSystem` for bullets). |
| `CollisionComponent` | Yes | `Rectangle bounds`, `Rectangle worldBounds`, `float baseOffsetX/Y`, `float currentOffsetX/Y` | AABB bounding box, relative-sized (positioned each frame from `TransformComponent.position`). `worldBounds` is the absolute map position. `baseOffsetX/Y` is the centering anchor. `currentOffsetX/Y` is the smoothed directional offset. |
| `PlayerComponent` | No | `int health/maxHealth = 3`, `int coins = 0`, `int items/maxItems = 0/30`, `int facingDirection = 1` (-1 left, 1 right), `int jumpCount`, `int maxJumps = 2`, `boolean isWallClimbing`, `Timer shootCooldown`, `Timer meleeCooldown`, `Timer meleeAttack`, `boolean meleeHasHit`, `Timer hitInvulnerability`, `Timer hurtTimer`, `boolean interactPressed`, `boolean nearExit` | Flag + state component for the single player entity: health, currency, ammo, traversal (double jump, wall climb), combat (melee/ranged) state, the post-hit invulnerability grace period, the short hit-stun window (`hurtTimer` — input lock + HURT animation window, started alongside `hitInvulnerability` by `PlayerDamageResolver`), and the exit-gate interact flow (`interactPressed` is a one-shot per-frame flag set by `PlayerInputSystem`, `nearExit` drives the touch UI prompt and is set by `LevelExitSystem`). All of these survive a `LevelManager.loadLevel(...)` swap untouched except `interactPressed`/`nearExit`, which are explicitly reset (along with transient movement state) since it's literally the same component instance kept alive across levels. |
| `BulletComponent` | Yes | `float damage`, `float lifetime` | Marks a spawned projectile entity; despawns once `lifetime` elapses without a hit. `damage` is `0` for enemy-fired bullets (see `EnemyBulletComponent`), since those damage the player via the flat contact-damage rule, not HP damage. |
| `EnemyComponent` | No | `float health = 10`, `float speed = 20`, `int direction = 1` (1=right, -1=left), `float patrolRange = 32`, `float originX`, `Timer hitStun`, `Timer postHitIdle`, `boolean isDead = false`, `Timer deathTimer`, `int roomIndex = -1` | Damageable enemy with simple back-and-forth patrol movement resolved by `EnemySystem` (direction/velocity are stored here so the system stays stateless between entities); damage is applied externally by `CollisionSystem`/`MeleeAttackSystem`, which also start `hitStun` (a post-hit grace period during which patrol AI pauses and further hits are ignored). When health reaches zero, `isDead` is set to `true` and `deathTimer` is started to track the death animation duration. `roomIndex` is the index into `RoomState.rooms` of the Room rectangle this enemy was spawned inside of (set by `EntityFactory` from the spawn point's containment), or `-1` if it wasn't inside any known room (always active); `EnemySystem`/`EnemyShootSystem` freeze this enemy's patrol/firing while `roomIndex` doesn't match `RoomState.activeRoomIndex`. After `hitStun` ends, `postHitIdle` is used to pause the enemy for a brief period before resuming patrol. |
| `FlyingEnemyComponent` | No | `float bobAmplitude = 8`, `float bobFrequency = π` (rad/s), `float bobTime` | Layered on top of `EnemyComponent` to tag an enemy as immune to gravity; checked by `MovementSystem`, which skips the gravity/wall-slide velocity-Y update entirely when present, so the entity hovers at whatever height it's at (no bobbing without a horizontal velocity source, since gravity never pulls it back). `EnemySystem` also drives a time-based vertical bob wave into `movement.velocity.y` from `bobAmplitude`/`bobFrequency`/`bobTime` every non-stunned frame, so the flyer flaps up/down around its spawn height while patrolling; `bobTime` freezes whenever patrol AI is paused (hit-stun). Horizontal patrol logic needs no changes: a flying enemy is never `grounded`, so it turns around purely via `patrolRange`/`originX`. |
| `EnemyShooterComponent` | No | `Timer shootCooldown`, `float shootInterval = 5` | Layered on top of `EnemyComponent` to tag an enemy as able to fire a bullet periodically; resolved by `EnemyShootSystem`, which additionally only lets a ready shooter actually fire while its `EnemyComponent.roomIndex` is the currently active Room (see `EnemyShootSystem` row below). The enemy still patrols normally (driven by `EnemySystem`, which already matches its family). |
| `EnemyBulletComponent` | Yes | *(none — empty marker)* | Tags a bullet entity as enemy-fired (as opposed to the player's own bullets), attached alongside `BulletComponent` by `EnemyShootSystem`. `CollisionSystem` excludes it; `EnemyBulletCollisionSystem` processes it instead. |
| `CoinPickupComponent` | No | `int amount = 1` | Marker for a coin pickup; grants `amount` to `PlayerComponent.coins` (uncapped) on pickup. |
| `DaggerPickupComponent` | No | `int amount = 5` | Marker for a dagger pickup; grants `amount` to `PlayerComponent.items`, capped at `maxItems`. |
| `ChestComponent` | No | `boolean opened = false`, `Timer disappearTimer` | Tracks a chest's open/disappear state after being melee-struck; drops coins on disappear. |
| `PoppedItemComponent` | No | *(none — empty marker)* | Tags a pickup entity (currently only chest-dropped coins) that was launched with an initial `MovementComponent.velocity`; checked by `MovementSystem`, which zeroes `velocity.x` the moment `grounded` first becomes true so it comes to a dead stop on landing instead of sliding (there's no ground friction elsewhere). |
| `LevelExitComponent` | No | `String nextLevelPath = ""` | Marks an exit-gate entity as an actual level-transition trigger (as opposed to a purely decorative gate); added by `EntityFactory.createExitGate(...)` only when the gate's Tiled object has a `nextLevel` custom property. Read by `LevelExitSystem`, which hands `nextLevelPath` to `LevelManager.loadLevel(...)`. |
| `ParticleComponent` | Yes | `ParticleEffect effect`, `boolean isDead = false`, `float delay = 0`, `boolean started = false`, `float scale = 1` | Marks a one-shot visual particle-effect entity, created by `ParticleHelper.spawnParticle(...)` as a `new ParticleEffect(template)` clone (shares the template's textures; the clone does **not** own them, so it is never `dispose()`d). `started` becomes `true` once the effect is started (after `delay` elapses), `isDead` is set by `ParticleSystem` when the effect completes, and `effect`/`delay`/`scale` drive the spawn. `reset()` (pooled) calls `effect.reset()` then nulls it. Consumed by `ParticleSystem`. |

### `Mappers` (`com.axehigh.platformer.ecs.components.Mappers`)
Central holder of shared `ComponentMapper<T>` instances (one static field per component above: `TRANSFORM`, `TEXTURE`, `ANIMATION`, `MOVEMENT`, `COLLISION`, `PLAYER`, `BULLET`, `ENEMY_BULLET`, `ENEMY`, `FLYING`, `ENEMY_SHOOTER`, `DAGGER_PICKUP`, `COIN_PICKUP`, `CHEST`, `POPPED_ITEM`, `LEVEL_EXIT`, `PARTICLE`). **Every system must read/write components through these mappers** instead of creating new `ComponentMapper.getFor(...)` calls. Adding a new component requires adding its mapper here.

### `RoomState` (`com.axehigh.platformer.map.RoomState`, not an ECS `Component`)
A plain shared-state holder (same sharing pattern as the shared `collisionRects` array, not a `Component`/`System`) built from a map's **"Rooms" object layer**: `Array<Room> rooms` (every room rectangle from that layer, parsed by `MapLoader.getRooms()`) and `int activeRoomIndex = -1` (index into `rooms` of whichever one currently contains the player). Exposes `findRoomIndexContaining(float x, float y)`, a linear scan returning the first room rectangle containing that point, or `-1`. A single instance is created once in `GameScreen.show()`, passed to `CameraSystem`, `EnemySystem`, `EnemyShootSystem`, `DebugRenderSystem`, `EntityFactory.spawnObjects(...)`, and `LevelManager`; `LevelManager.loadLevel(...)` clears+refills `rooms` in place on every level swap, so every holder sees the new level's rooms immediately, no re-wiring needed — identical in spirit to how `collisionRects` is shared.

### `Room` (`com.axehigh.platformer.map.Room`, not an ECS `Component`)
A plain `Rectangle` subclass carrying one extra field — the camera-mode override. `Array<Room>` is what `RoomState.rooms` actually holds, so any consumer reading a room as a plain `Rectangle` (e.g. `DebugRenderSystem`, `CameraSystem`) keeps working unchanged. Field: `Mode mode` (`AUTO`, `FLIP`, or `SCROLL`), parsed by `MapLoader.getRooms()` from the room's optional `camera` Tiled custom property (`"flip"`/`"scroll"`; anything else = `AUTO`). `CameraSystem` resolves the effective mode **per axis**: `AUTO` infers from size (room bigger than the viewport on an axis → scroll, otherwise → static center), `FLIP` forces static room-centered framing, `SCROLL` forces dead-zone scrolling (still falling back to centering when the room is smaller than the viewport, since there is nothing to scroll).

### `Timer` (`com.axehigh.platformer.util.Timer`)
A plain (non-`Component`, non-`Poolable`) helper class embedded as a field inside components that need a countdown — not an Ashley concept, just a reusable value holder. API: `start(float duration)`, `update(float deltaTime)` (clamped at 0, no-op once done), `isActive()`, `isDone()`, `getRemaining()`, `reset()`. Used by `PlayerComponent` (`shootCooldown`, `meleeCooldown`, `meleeAttack`, `hitInvulnerability`, `hurtTimer`), `ChestComponent` (`disappearTimer`), `EnemyComponent` (`hitStun`), and `EnemyShooterComponent` (`shootCooldown`); **any new cooldown/countdown/grace-period field should use `Timer` instead of a raw `float`.**

### `EnemyDamageResolver` (`com.axehigh.platformer.ecs.systems.EnemyDamageResolver`)
A package-private static helper (not a `Component`/`System`) shared by `CollisionSystem` (bullet hits) and `MeleeAttackSystem` (melee hits) so both damage sources apply enemy hit-reaction identically. `applyHit(Entity enemyEntity, EnemyComponent enemy, MovementComponent movement, float damage, int knockbackDirection, boolean isFlying)`: if `enemy.isDead` or `enemy.hitStun.isActive()`, the hit is fully ignored (returns `false`); otherwise subtracts `damage` from `enemy.health`. If health reaches 0, sets `enemy.isDead = true`, zeroes `movement.velocity`, starts `enemy.deathTimer` based on the `DEATH` animation duration, and returns `true`. Otherwise, sets `movement.velocity.x` to a knockback pop (`90` u/s horizontal away from the attacker) and, unless `isFlying`, a `140` u/s vertical hop, then starts `enemy.hitStun` for a duration matching the `HURT` animation (min `0.3s`) and returns `false`.

### `PlayerDamageResolver` (`com.axehigh.platformer.ecs.systems.PlayerDamageResolver`)
The player-side counterpart of `EnemyDamageResolver`: a package-private static helper shared by `EnemyContactSystem` (touch) and `EnemyBulletCollisionSystem` (enemy bullet) so both damage sources apply the player's hit-reaction identically. `applyHit(Entity playerEntity, PlayerComponent player, MovementComponent movement, int knockbackDirection, float unitScale)`: if `player.isDead` or `player.hitInvulnerability.isActive()`, the hit is fully ignored (returns `false`); otherwise decrements `player.health` (clamped at 0), sets `movement.velocity.x` to a small knockback push (`60` u/s horizontal, direction given by `knockbackDirection` — no vertical pop), starts `player.hurtTimer` for a duration matching the `HURT` animation (min `0.3s`, so the clip visibly plays once), and starts `player.hitInvulnerability` for `1.0s`. Returns `true` if the hit applied. `HIT_INVULNERABILITY_DURATION = 1.0f` is the single source of truth for the grace period both callers previously hard-coded.

## 2. Systems (`com.axehigh.platformer.ecs.systems`)

Each row lists the Ashley base class, the entity `Family` it processes (as configured in its constructor), and its responsibility. "Priority" refers to the value passed in by `GameScreen` (lower runs first); systems are also usable with priority `0` via their no-arg/short constructors for tests or other screens.

| System | Base class | Family | Responsibility |
|---|---|---|---|
| `PlayerInputSystem` | `IteratingSystem` | all: `PlayerComponent`, `MovementComponent`, `TransformComponent`, `CollisionComponent` | Reads keyboard **and** touch-UI input (state pushed in via `setTouchLeft/Right`, `requestTouchJump/Melee/Shoot`) and converts it into: horizontal velocity + `facingDirection`; jump velocity (gated by `jumpCount < maxJumps`); melee trigger (gated by `meleeCooldown.isDone()`, starts `meleeAttack` for the duration of the `ATTACKING` animation); ranged shot (gated by `shootCooldown.isDone()` and `items > 0`, spawns a bullet entity via `PooledEngine` with `BULLET_DAMAGE = 10`). A ground jump (started while `movement.grounded`) also spawns a smoke puff at a random spot under the player's feet via `ParticleHelper.spawnSmallSmoke(...)`; air/double jumps spawn none. While `player.hurtTimer.isActive()` the player is in **hit-stun lock**: horizontal input is left untouched (so the knockback pop set by `PlayerDamageResolver` isn't overwritten) and jump/melee/shoot requests are ignored — cooldowns still tick and `interactPressed` is still set. Touch-request flags are reset every `update()` after processing. |
| `EnemySystem` | `IteratingSystem` | all: `EnemyComponent`, `MovementComponent`, `TransformComponent`, `CollisionComponent` | Simple back-and-forth patrol AI, platform-edge awareness, hit-stun/post-hit-idle pausing, dead-enemy lifecycle, and Room-based activation. Each frame first checks `if (enemy.isDead)`: if so, ticks `deathTimer` and removes the entity once done. Otherwise ticks `enemy.hitStun` and `enemy.postHitIdle`. If `hitStun` just ended, starts `postHitIdle` (0.5s). Then checks Room-based activation; if inactive, freezes enemy. Otherwise, while `hitStun` or `postHitIdle` active, skips patrol and zeroes velocity (during idle only); otherwise drives patrol logic (edge awareness, wall blocking, origin-range). A `FlyingEnemyComponent` also gets a vertical bob. Runs **before** `MovementSystem`. |
| `EnemyShootSystem` | `IteratingSystem` | all: `EnemyComponent`, `EnemyShooterComponent`, `TransformComponent`, `CollisionComponent` | Drives shooter-enemy firing: caches a `PooledEngine` in `addedToEngine`; each frame ticks `shooter.shootCooldown`, skips firing entirely while `enemy.isDead` or `enemy.hitStun.isActive()`, and once `isDone()` **and** `enemy.roomIndex` is either `-1` or equal to `RoomState.activeRoomIndex`, spawns a bullet. |
| `MovementSystem` | `IteratingSystem` | all: `TransformComponent`, `MovementComponent`, `CollisionComponent`; **excludes** `BulletComponent` | Applies gravity (or reduced wall-slide gravity while `isWallClimbing`), unless the entity has a `FlyingEnemyComponent` (gravity/wall-slide velocity-Y update is skipped entirely, so it holds its spawn height). Clamps velocity to `maxSpeedX/Y`, integrates position on X then Y separately with AABB resolution against the static `collisionRects` set (from `MapLoader`). For the player, also smoothly lerps `collision.currentOffsetX` based on `facingDirection` and `PlayerOffsetRight/Left` to provide directional reach or alignment. If the entity has a `PoppedItemComponent` and just became `grounded`, also zeroes `velocity.x` so it stops dead on landing instead of sliding. Drives player-only side effects: on a landing from a jump (`grounded` true while `player.jumpCount > 0`, checked just before the reset — so a jump must have happened; falling off a ledge keeps `jumpCount == 0` and spawns nothing) spawns a smoke puff under the player via `ParticleHelper.spawnSmallSmoke(...)` at a **random X across the collision width**, scaled by fall impact speed (`5.0` + up to `5.0` more as `|fallSpeed| / maxSpeedY` approaches `1`, i.e. longer falls → bigger puff) — it needs a `PooledEngine`, so `addedToEngine` keeps a guarded reference and skips under a plain `Engine` (e.g. headless tests); then resets `jumpCount` when grounded, sets `isWallClimbing`/`jumpCount = 1` on a horizontal wall hit while airborne (skipped while `player.hurtTimer.isActive()` so a knockback push into a wall doesn't fake a wall-grab), and clears `isWallClimbing` on release. |
| `CollisionSystem` | `IteratingSystem` | all: `BulletComponent`, `TransformComponent`, `MovementComponent`, `CollisionComponent`; **excludes** `EnemyBulletComponent` | Owns **player-bullet-only** movement integration (bullets are excluded from `MovementSystem`) and resolution: counts down `lifetime` (removes on expiry), moves the bullet, removes it on wall overlap (`collisionRects`), and on enemy overlap resolves the hit via `EnemyDamageResolver.applyHit(...)` (knockback direction = the bullet's own travel direction, `isFlying` = whether the hit enemy has `FlyingEnemyComponent`), and always removes the bullet. Looks up the enemy family once in `addedToEngine`. Excludes `EnemyBulletComponent` so it never double-processes an enemy-fired bullet (handled instead by `EnemyBulletCollisionSystem`). |
| `EnemyBulletCollisionSystem` | `IteratingSystem` | all: `BulletComponent`, `EnemyBulletComponent`, `TransformComponent`, `MovementComponent`, `CollisionComponent` | Mirrors `CollisionSystem`'s structure for **enemy-fired** bullets only, but resolves the hit case against the player instead of an enemy: caches the single player entity once in `addedToEngine` (mirrors `PickupSystem`); counts down `lifetime` (removes on expiry), moves the bullet, removes it on wall overlap, and on player overlap always removes the bullet, additionally resolving the hit via the shared `PlayerDamageResolver` (knockback direction = the bullet's own travel direction, sign of `MovementComponent.velocity.x`) so the player reacts exactly as if touched by an enemy — the same shared `hitInvulnerability` grace period means a shot and a touch share one window. |
| `MeleeAttackSystem` | `IteratingSystem` | all: `PlayerComponent`, `TransformComponent`, `CollisionComponent` | While `meleeAttack.isActive()`, computes the current `ATTACKING` animation frame from the swing's elapsed time (`animationDuration − meleeAttack.getRemaining()`) and maps it to a per-frame horizontal reach via the sprite's reach table — `SpriteConstants.PLAYER_ATTACK_REACH` (`{ 0, 12, 16, 24, 0 }` world units before `unitScale`, one entry per swing frame — `0` = windup/recovery frames can't hit, so the hitbox only exists while the blade is extended). The reach tables live in `SpriteConstants` (the per-sprite geometry class, mirroring the existing `Player*`/`Enemy*` collision-box grouping) prefixed by sprite, so a future sprite with a different attack animation defines its own `*_ATTACK_REACH` table there and gets its own reach without touching this system; `PLAYER_MAX_ATTACK_REACH` is the fallback used when no `ATTACKING` animation is registered, so a strike still always connects. Builds the strike `Rectangle` offset from the player's bounds in `facingDirection` (full collision height, horizontal reach only; kept alive as `strikeBounds` and always exposed via `getActiveStrikeBounds()`, `null` while idle/on non-hitting frames, so `DebugRenderSystem` can draw it in red). On live frames with `!meleeHasHit`, checks the enemy family first, then the chest family (both looked up once in `addedToEngine`). Resolves an enemy hit via `EnemyDamageResolver.applyHit(...)` (damage read from `player.swordDamage`, knockback direction = `facingDirection`, `isFlying` = whether the hit enemy has `FlyingEnemyComponent`), **or** opens an unopened chest (swaps texture to `gfx/chest_open.png`, starts `disappearTimer`); either way sets `meleeHasHit = true` so one swing hits at most once. Ticks `meleeAttack` down every frame it runs. |
| `PickupSystem` | `IteratingSystem` | one of: `DaggerPickupComponent`, `CoinPickupComponent` | Resolves the single player entity once in `addedToEngine`, then per pickup entity checks AABB overlap against the player. On overlap: dagger pickups increment `player.items` (capped at `maxItems`), coin pickups increment `player.coins` (uncapped); either way removes the pickup entity. |
| `ChestSystem` | `IteratingSystem` | all: `ChestComponent`, `TransformComponent` | Owns the opened-chest lifecycle: for chests with `opened == true`, ticks `disappearTimer` down; once `isDone()`, removes the chest and spawns a random number (`MathUtils.random(2, 6)`) of coin pickups (via `EntityFactory.createPoppedCoinPickup`) at the chest's last position, each launched with a random upward (`80`-`140` u/s) and horizontal (`±40` u/s) velocity so it pops up and out before `MovementSystem`'s gravity/collision settles it on the ground. |
| `EnemyContactSystem` | `IteratingSystem` | all: `EnemyComponent`, `TransformComponent`, `CollisionComponent` | Resolves enemy-vs-player contact damage: resolves the single player entity once in `addedToEngine` (mirroring `PickupSystem`); overrides `update(float deltaTime)` to tick `player.hitInvulnerability` **and** `player.hurtTimer` exactly **once per frame** (before `super.update()` iterates enemies, avoiding a multi-tick bug with 2+ enemies), then per enemy checks AABB overlap against the player. On overlap while `!enemy.isDead`, routes the hit through the shared `PlayerDamageResolver` (knockback direction = away from the enemy's collision center X, i.e. which side of the enemy the player's center is on) so a single frame with multiple overlapping enemies still only costs one life. Note: the `hitInvulnerability` timer it ticks/restarts is the same one `EnemyBulletCollisionSystem` reads, so contact and shot damage share one grace period. |
| `LevelExitSystem` | `IteratingSystem` | all: `LevelExitComponent`, `TransformComponent`, `CollisionComponent` | Drives the exit-gate proximity/interact flow, mirroring `EnemyContactSystem`'s single-player-resolved-once pattern: resolves the single player entity once in `addedToEngine`; each frame first resets `player.nearExit = false`, then per gate builds a sensor `Rectangle` (the gate's own `CollisionComponent.bounds` inflated by `SENSOR_PADDING = 6` units on every side) and checks it against the player's AABB. On overlap sets `player.nearExit = true` (drives the touch UI prompt); if `player.interactPressed` is also `true` that same frame, consumes the flag (`= false`), builds/persists a `SaveData` snapshot (level path, core stats, merged `completedLevelIds`) via `SaveManager.save(...)`, and calls `LevelManager.loadLevel(exit.nextLevelPath, playerEntity)` to perform the actual level transition. Holds a `LevelManager` reference passed in via its constructor. |
| `PlayerDeathSystem` | `IteratingSystem` | all: `PlayerComponent` | Detects the player's health reaching 0: each frame, while an internal `triggered` guard is still `false`, checks `player.health <= 0`; on the first frame this is true, sets `triggered = true` and invokes a `Runnable onDeath` callback passed in via its constructor (fires exactly once per level instance — a fresh `PlayerDeathSystem` is created on every `GameScreen.show()`/level (re)load, so retrying naturally resets the guard). `GameScreen` wires the callback to flip a `gameOverActive` flag and show the Game Over dialog. |
| `CameraSystem` | `EntitySystem` (not iterating; single-purpose) | all: `PlayerComponent`, `TransformComponent` (resolved once in `addedToEngine`) | Hybrid flip-screen / dead-zone scroll camera: each frame finds which `RoomState.rooms` rectangle contains the player (`RoomState.findRoomIndexContaining(...)`, updating `RoomState.activeRoomIndex` when found) and frames the camera per axis according to that room's resolved mode (see the `Room` section): a **flip axis** (room no bigger than the viewport on that axis, or `Mode.FLIP`) keeps the camera locked to the room's center — static, viewport allowed to overshoot the room's edges — and snaps instantly to that center the moment the player enters the room; a **scroll axis** (room bigger than the viewport, or `Mode.SCROLL`) holds the camera still while the player roams inside a dead zone (screen edges inset by `GameConstants.CAMERA_SCROLL_MARGIN`) and only scrolls once the player crosses the margin, clamped so the viewport never crosses the room's edges. Rooms smaller than the viewport never scroll, even when forced. On a room change the camera snaps (no lerp/easing). The placement logic lives in a `public static snapToRoom(OrthographicCamera, RoomState, float x, float y)` method so `GameScreen`/`LevelManager` can reuse it verbatim to frame the starting room right after a level swap. Replaces the old fixed `VIRTUAL_WIDTH`/`HEIGHT` flip-screen grid entirely. |
| `AnimationSystem` | `IteratingSystem` | all: `AnimationComponent`, `TextureComponent` | Resolves `currentState` from entity state: for players (`DEATH` > `HURT` > `ATTACKING` > `WALL_CLIMBING` > `JUMPING`/`DOUBLE_JUMPING` > `RUNNING` > `WALKING` > `IDLE`); for enemies (`DEATH` > `HURT` > `WALKING` > `IDLE`). Player `HURT` is keyed on `player.hurtTimer` (the short hit-stun window), **not** the full `hitInvulnerability` — so the non-looping hurt clip plays exactly once and the pose isn't frozen. After the hurt window ends but while `hitInvulnerability` is still active (and not dead), the state returns to normal and the system blinks the player: it accumulates `AnimationComponent.blinkTimer` and nulls `TextureComponent.region` on alternating ~10Hz phases (a null region is skipped by `RenderSystem`), communicating the remaining invulnerability without a frozen pose. Mirrors the sprite by setting `transform.scale.x = abs(scale.x) * direction` (from `player.facingDirection` or `enemy.direction`). Resets `stateTime` on state change, otherwise accumulates it, then writes the resolved animation's key frame into `TextureComponent.region`. |
| `TiledMapRenderSystem` | `EntitySystem` (not iterating), `Disposable` | n/a (holds the `TiledMap`/`OrthogonalTiledMapRenderer` directly, no entity family) | Renders the Tiled map's background/collision tile layers each frame via `OrthogonalTiledMapRenderer.setView(camera)` + `render()`. Must be `dispose()`d when the screen changes. `setMap(TiledMap map)` disposes the current `OrthogonalTiledMapRenderer` and builds a new one around the new map — used by `LevelManager` to swap levels without recreating the system (its priority and place in the engine never change). |
| `RenderSystem` | `SortedIteratingSystem` (sorted by a `ZComparator` on `TransformComponent.z`, ascending) | all: `TransformComponent`, `TextureComponent` | Draws every renderable entity via the shared `SpriteBatch`, sized from the texture region times `transform.scale`, honoring `transform.rotation`. For entities with `CollisionComponent`, anchors the sprite such that the character's center (compensated for `currentOffsetX/Y` and flip) remains locked to the collision box center. Wraps `batch.begin()/end()` around the sorted iteration in its own `update()` override. |
| `ParticleSystem` | `IteratingSystem` | all: `ParticleComponent`, `TransformComponent` | Drives every live one-shot particle effect to completion: per entity, counts `delay` down before starting; each frame repositions the effect to `TransformComponent.position`, calls `ParticleEffect.update(deltaTime)` and `ParticleEffect.draw(batch)` (its own `update()` override wraps `batch.begin()/end()` with `camera.combined` projection, mirroring `RenderSystem`), and once `isComplete()` sets `isDead = true` and removes the entity (so `PooledEngine` frees the `ParticleComponent`, whose `reset()` resets the effect). Leftover particle entities are cleaned automatically on a level swap because `LevelManager.loadLevel(...)` removes every non-player entity. Runs **after** `RenderSystem` so particles draw on top of entities, **before** `DebugRenderSystem`. |
| `DebugRenderSystem` | `EntitySystem` (not iterating), `Disposable` | all: `TransformComponent`, `CollisionComponent` (resolved once in `addedToEngine`) | Debug-only collision/room visualizer (see AGENTS.md "Debugging"): toggled on/off by SHIFT+D (`Input.Keys.SHIFT_LEFT`/`SHIFT_RIGHT` + `D`, checked every frame regardless of enabled state) or via the pause menu's "Collision Debug" button (`DebugRenderSystem.isDebugEnabled()`/`setDebugEnabled(...)`; the flag is **static**, so it survives level reloads within a session); while enabled, draws every entity's `CollisionComponent` AABB (lime) at `transform.position` sized by `collision.bounds`, the static map `collisionRects` (yellow), every `RoomState.rooms` rectangle (cyan, or orange for whichever one is `activeRoomIndex`), and the player's live melee strike hitbox (red, pulled from `MeleeAttackSystem.getActiveStrikeBounds()`, resolved once in `addedToEngine` via `engine.getSystem(...)`) — all via its own `ShapeRenderer` in `ShapeType.Line`. No-op (skips the `ShapeRenderer` block entirely) while disabled. Must run **after** `RenderSystem` so its `ShapeRenderer` begin/end block never overlaps the `SpriteBatch` block. Owns and `dispose()`s its own `ShapeRenderer`. |

### System wiring & priority order (`GameScreen.show()`)
Systems are added to the `PooledEngine` in this priority order (lower runs first each frame); `EnemySystem`/`EnemyShootSystem` share priority `4`, `CollisionSystem`/`EnemyBulletCollisionSystem` share priority `6`, and `MeleeAttackSystem`, `PickupSystem`, `ChestSystem`, `EnemyContactSystem`, `LevelExitSystem`, and `PlayerDeathSystem` share priority `8` — relative order within each shared tier is not meaningful:

1. `PlayerInputSystem` — priority `0`
2. `EnemySystem` — priority `4`
3. `EnemyShootSystem` — priority `4`
4. `MovementSystem` — priority `5`
5. `CollisionBoundsSystem` — priority `6`
6. `CollisionSystem` — priority `7`
7. `EnemyBulletCollisionSystem` — priority `7`
8. `MeleeAttackSystem` — priority `8`
9. `PickupSystem` — priority `8`
10. `ChestSystem` — priority `8`
11. `EnemyContactSystem` — priority `8`
12. `LevelExitSystem` — priority `8`
13. `PlayerDeathSystem` — priority `8`
14. `CameraSystem` — priority `9`
15. `AnimationSystem` — priority `10`
16. `TiledMapRenderSystem` — priority `20`
17. `RenderSystem` — priority `30`
18. `ParticleSystem` — priority `35`
19. `DebugRenderSystem` — priority `40`

This ordering matters: input must run before movement/collision resolve it the same frame; enemy AI (patrol + shooting) must set velocity/spawn bullets before `MovementSystem` integrates them; melee/pickup/chest/enemy-contact/enemy-bullet-collision/level-exit/player-death must run after collision-affecting movement but before the camera snaps and animation/rendering read the resulting state; map rendering must happen before entity rendering so entities draw on top. `LevelExitSystem` runs at the same tier since a level transition it triggers must be fully applied (new map, new entities, repositioned player) before `CameraSystem` snaps to the player's (now brand new) room the same frame. `PlayerDeathSystem` runs at the same tier since health decrements from damage systems above it must be visible the same frame it checks `health <= 0`.

### `LevelManager` (`com.axehigh.platformer.map.LevelManager`, not an ECS `Component`/`System`)
Owns in-place level transitions on behalf of `LevelExitSystem`: `loadLevel(String tmxPath, Entity player)` loads a new `MapLoader`, calls `TiledMapRenderSystem.setMap(...)`, clears+refills the shared `collisionRects` array **and** the shared `RoomState.rooms` array in place (so `MovementSystem`/`EnemySystem`/`CollisionSystem`/`EnemyBulletCollisionSystem`/`DebugRenderSystem`/`CameraSystem` all see the new level's walls/rooms immediately, no re-wiring), removes every engine entity except the given player, disposes the old `MapLoader`, respawns the new level's objects via `EntityFactory.spawnObjects(...)` (which assigns each spawned enemy's `roomIndex` from the new `RoomState`), repositions the player's `TransformComponent` to the new map's `playerStart`, resets its transient `MovementComponent` (`velocity`, `grounded`) and `PlayerComponent` flags (`jumpCount`, `isWallClimbing`, `interactPressed`, `nearExit`) while leaving all stat fields (`health`, `coins`, `items`, ...) untouched, and calls `CameraSystem.snapToRoom(...)` to place the camera in the new starting room. `dispose()` disposes whichever `MapLoader` is currently active. Constructed once in `GameScreen.show()` and never rebuilt; the player `Entity`/`PooledEngine` are never destroyed across a level swap, which is why every persistent `PlayerComponent` field survives for free.

## 3. Adding/removing/changing an ECS element — checklist
When you add, remove, or edit a `Component` or `System`:
1. Update the relevant table row(s) above (fields, family, priority, responsibility).
2. If the change affects gameplay-visible mechanics (movement, combat, traversal, enemy behavior, pickups, etc.), also update `resources/docs-ai/gameplay.md` per the `AGENTS.md` "Gameplay Documentation Sync" rule — the two docs are complementary: this file describes the ECS *shape*, `gameplay.md` describes the *mechanics/logic* built on top of it.
3. If a new component needs cross-system lookups, add its `ComponentMapper` to `Mappers`.
4. If a new system is registered, add it to `GameScreen.show()` with an explicit priority constant and update the "System wiring & priority order" list above.
